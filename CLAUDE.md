## Commands

- `tools/test.sh` runs every gdUnit4 suite headless; exit 0 pass, 100 failures, 105 script errors, 1 if no tests found. `tools/test.sh -a res://tests/<file>.gd` runs one suite. The engine runs at `--fixed-fps 60` by default (a 1/60 s step a loop iteration, never waiting on the wall clock); `--realtime` paces it on the wall clock as the game is; `-v` streams the full output; both flags come before `-a` (a flag after `-a` is refused, before the import step). It prints a digest (each failed test with its report, script errors, the summary line) from its own `reports/test_<pid>.log`, moved to `reports/test.log` at exit (with two runners, the last to finish owns it). Read the log only when the digest is not enough.
- `tools/check_boot.sh` boots the main scene headless and fails on any `ERROR:`/`WARNING:` line, then runs the reload probe (`tools/reload_probe.gd` under `--fixed-fps 60`: Play, Restart, a fall to the gate screen, the grounds, Quit to title, the Ludus's top door, tier 1's lift, a yield; then tier 2's: `unlock_tier(2)` on the probe's profile, the Hypogeum's `lift:2` risen open, the 56x30 run, R (the reload keeps tier 2), Quit to title; each reload asserted a new Main; `RELOAD_PROBE ok`). Godot exits 0 even when the main scene fails to load, so never use its exit code alone.
- `tools/smoke.sh [idle|move|combat|kill|round|fall|wake|pick|roar|boo|title|pause|boss|grounds|rooms|talk|tier2|pair]` opens a window for a few seconds, drives input in physics ticks, and writes `reports/smoke_<scenario>.png` plus `SMOKE_` lines; all but `idle`, `move`, and `combat` assert their key lines. `round`, `fall`, `wake`, `pick`, `roar`, and `boo` run on `tools/smoke_series.tres` (two rounds of one chaser), `boss` on `tools/smoke_boss_series.tres`, `pair` on `tools/smoke_pair_series.tres` (one wave of the beast and the handler, 28x15); `tier2` on the shipped tier 2 (`RunState.set_tier(2)` before Main's `_ready`, the runner off, its bodies placed by hand beside the player); `grounds`, `rooms`, and `talk` set `flags.returned` (`rooms` also `spoliarium_seen`) on the scratch profile and Play into the Ludus. Asserted lines and extra captures: `kill` `SMOKE_KILLS 1`; `round` `SMOKE_ROUND 1`; `fall` `SMOKE_VERDICT up`, `SMOKE_NARRATOR verdict_up`, `SMOKE_GATE Porta Triumphalis` (`smoke_fall_verdict.png` at the thumb; the end capture is the gate screen over the black, dark by design); `wake` (`verso`) `SMOKE_GATE Porta Libitinaria`, `SMOKE_WAKE spoliarium prone=true`, `SMOKE_ROSE true` (`smoke_wake_prone.png`; `SMOKE_WAKE_LINE` unasserted); `pick` `SMOKE_MENU_OPEN true`, `SMOKE_CROWD_LINE crowd.<name>`, `SMOKE_UPGRADE <id>` (`smoke_pick_menu.png`); `roar` (at `FavourRules.MAX`) `SMOKE_ROAR 4`, `SMOKE_CROWD_ROARS 2` (`smoke_roar_menu.png`); `boo` (at a Boo) the crowd's line and `SMOKE_BOO_LOCKED <index>` (`smoke_boo_menu.png`); `title` `SMOKE_TITLE played=true paused=false` (`smoke_title_screen.png`); `pause` `SMOKE_PAUSE open=true paused=true` (`smoke_pause_menu.png`); `boss` `SMOKE_BOSS_FAVOUR 100` at its arrival (`smoke_boss_arrival.png`), `SMOKE_BOSS_HP n of <max>` below max, `SMOKE_BOSS_BAR true`; `grounds` `SMOKE_ARRIVAL <pool>.<name> open=true`, `SMOKE_GROUNDS_WORD lanista.<name>`, `SMOKE_GROUNDS post` (`smoke_arrival.png`, `smoke_grounds_key.png`; the end capture has the training panel up); `rooms` `SMOKE_ROOMS ludus armamentarium sanitarium hypogeum spoliarium` (`smoke_room_<id>.png`, `smoke_room_door_key.png`); `talk` `SMOKE_TALK veteran.<name> open=false` (`smoke_talk_mark.png`, `smoke_talk_key.png`, `smoke_talk_box.png`, `smoke_talk_choices.png`); `tier2` `SMOKE_TIER 2 56x30`, `SMOKE_ARROW true` (`smoke_tier2_arrow.png`: a still chaser walked off the screen, its arrow at the edge), `SMOKE_CHARGE_LINE true` (`smoke_tier2_line.png`: a charger mid-wind-up, its line through the player), `SMOKE_BANNER <n> hastened` (`smoke_tier2_banner.png`: a bearer's ring over two still chasers; counted from the group `enemies`, never `Room/Enemies`' children); `pair` `SMOKE_BOSS_FAVOUR 100`, `SMOKE_BOSS_BARS 2` (`smoke_pair_bars.png` after a second of shooting the first body; `SMOKE_BOSS_FILLS` unasserted). The story's checks match a pool and a shape, never an event's name. Every scenario fails if it ran silent (`SMOKE_AUDIO 0`). A 30 s in-process watchdog (`watchdog: scenario hung`). Read the PNGs to verify visuals. The smoke tool and the reload probe use their own per-process scratch profiles (`user://smoke_profile_<pid>.cfg`, `user://probe_profile_<pid>.cfg`), never the player's save.
- `tools/story_lint.sh [res://dir]` lints the story (`data/story` by default) headless (`--import` first, then `tools/story_lint.gd` under the perl alarm): the catalog's errors, the lint's warnings (`[kind] message`), the flag map, the placeholder count, and `STORY_LINT errors=<n> warnings=<n> placeholders=<n>/<n>`; exit 1 on an error in the story (or when the summary is missing or a script error printed), 0 otherwise (warnings alone pass; `test_story_data.gd` wants none on the shipped story).
- `tools/release.sh [version]` publishes the built zips as the GitHub release `v<version>` of https://github.com/beben-games/2d-game (a `-rc` version is a pre-release; needs `gh auth login` and the commit pushed).
- `tools/run.sh [--seed=N] [--tier=N]` plays the game from the project with the Godot binary; the user's way to run locally. `--tier=N` fights that tier whatever the save has unlocked and skips the title (a replay aid: with `--seed=N` it replays a run of that tier; an unknown tier is refused with a warning, as a bad seed is); both are read once a process by `Main._apply_arguments` over `Main.user_args`.
- `tools/build.sh [version]` exports the tester zips (Windows x64 and Linux x64, release, `export_presets.cfg`, `docs/TESTERS.md` as the README) into `builds/` (gitignored). Needs the 4.7.2 export templates. The version comes from `config/version` in `project.godot`.
- `tools/gen_atlas.py` regenerates `data/atlas.json` from the tileset's tile list. Sprites are always looked up by name through `SpriteAtlas`; never hardcode atlas pixel coordinates.
- `tools/gen_icons.py` regenerates `data/icons.json` (icons by name from a (row, col) table on the Raven sheet). Headless Godot generators run as `source tools/godot.sh && perl -e 'alarm 120; exec @ARGV' "$GODOT_BIN" --headless --path . -s tools/<script>.gd </dev/null`: `gen_guns.gd` (the handgun sprite), `icon_sheet.gd` (every icon to `reports/icons.png`).
- Art tools (Python, `tools/art/`): `budget.py` prints what an art session may spend (`--left N` offline); `pixellab.py balance` is the REST client's check. The API key is read from the macOS login keychain (`tools/art/keys.py`, service `pixellab-api-key`) and never printed, logged, or written; `git config core.hooksPath tools/hooks` enables the pre-commit hook that refuses a staged key or `.env`.
- Godot binary: `source tools/godot.sh` exports `GODOT_BIN` (/Applications/Godot.app/Contents/MacOS/Godot, 4.7.2).

## Conventions

- Commits: no global git identity on this machine. Use `git -c user.name="Benjamin Zigh" -c user.email="78459259+beben-games@users.noreply.github.com" commit` and end messages with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- The repo is public at https://github.com/beben-games/2d-game (`origin`), code MIT (`LICENSE`), assets per `CREDITS.md`. Packs whose terms forbid reposting (Raven icons, the pistol sheet, the Minifantasy and Classic Monster sounds, the music loops, the reserve sets) are gitignored and never committed; they ship only inside the builds (`docs/ASSETS.md`). A new asset gets a `CREDITS.md` row with its license and an "In the repo" verdict before it is committed. Without them `IconAtlas` draws a placeholder (`ICON_MISSING`) and `Audio` plays silence.
- Commit Godot's generated `.uid` and `.import` files. `reports/` and `.godot/` are ignored. Never edit `addons/gdUnit4` (vendored upstream v6.2.1).
- The login shell is zsh; tool scripts are bash and are executed, never sourced.
- Physics layers: 1 player, 2 enemies, 3 player_shots, 4 enemy_shots, 5 walls (bits 1, 2, 4, 8, 16), 6 pickups (32: the coin pile, an `Area2D` masking 65, monitoring off until its toss lands), 7 player_dashing (64: the player's body layer during a dash; enemies never mask it, and a trigger that must see a dashing player masks 65, as the pile and every `Interactable` do). Player body mask 18 (walls, enemies), 16 while dashing; enemy bodies 19. Player shots mask 2 and enemy bolts 0; walls are the projectile's raycast against layer 5 (`Projectile.WALL_MASK`). Enemy bodies are solid; damage reaches the player only through the hurtbox. An enemy bolt carries `Projectile.ENEMY_BOLT_GROUP` from `scenes/enemies/enemy_bolt.tscn` itself (its motion `Projectile.velocity()`). A door's blocker and a cast member's lower body are `StaticBody2D`s on the walls' layer. A shielded enemy (`EnemyDef.shield`) blocks a player shot inside its front arc through `Enemy.blocks_shot(direction, pierce)`, asked duck-typed by `Projectile._on_body_entered` before `take_damage`, unless the shot's pierce is at least `Enemy.SHIELD_PIERCE` (3); a blocked shot with a bounce left reflects off the shield instead of dying (`ShieldRules.bounce`, the facing read duck-typed as the normal, `Projectile._bounce` shared with the wall's; it emits `shot_deflected`, neither `shot_bounced` nor `shot_blocked`: the wall bounce's sound and sparks, and to `Favour` a shot landed on the fight); the rules are `ShieldRules`. The shield's facing follows the enemy's movement at `shield_turn_degrees` a second and holds under a stun. The boss (`scenes/enemies/boss.tscn`) is an enemy body (layer 2, mask 19) in the group `boss`; only a `StaticBody2D` ends its charge; its summons carry the group `summoned`, which `WaveRunner` ignores. A charger's run masks walls only (`Enemy.CHARGE_MASK` 16) and adds a collision exception with every body of `enemies` and `player` each run tick (Godot's 2D cull honours either side), released at its skid's end (the brain's `done`) and on death (`_stop_passing_through`; a body still overlapping at the run's end keeps its exception until the two part, `_release_parted`); layer 2 stays, so the hurtbox and the shots find it. `Movement.hit_wall` (a `StaticBody2D` among the last slide's colliders) ends an enemy's or a boss's charge. A shot's damage is scaled by `damage_scale(direction)`, asked duck-typed after `blocks_shot` (a charger's back in its skid: `back_damage_scale` inside `back_arc_degrees`). A standard-bearer is never harmful (`is_harmful` false: no contact damage, no dare, no drain source) and still a kill; its banner writes `Enemy.haste` on the bodies it covers; its ring lives under `Room/Rings` (group `Enemy.RINGS_GROUP`, before `Piles` and `Enemies`), so `Room/Enemies` holds only enemies.
- Time: game code under `scripts/` times by `Clock.now_usec()` (the first autoload: the engine's unscaled step, the clock every `create_timer(t, true, false, true)` runs on; wall time in the game, 1/60 s a frame under `--fixed-fps`), never `Time.get_ticks_*`: Juice's trauma decay and hitstop end, Audio's `min_gap`, and the text box's reveal read it; the one exception is Audio's release loop at quit (the mixer's thread). Tools keep real time. `Clock` reads 0 before its `_ready`, so no autoload reads it in an initializer.
- Randomness: shot spread and the shooter's recover jitter use `RunState.rng`; placement that must depend only on seed and time uses `RunState.stream(name)`; cosmetic effects use the global RNG; the arena floor derives its own RNG from the seed. Every game caller names its stream through `RunState.stream_name(base)` (over the static `stream_name_for(base, tier)`, on `RunState.run_tier`): tier 1's spelling is unchanged (`spawn:<round>`, `piles:<round>`, `upgrades:...`, `lock:...`), a later tier's carries `t<n>` after the name's first part (`spawn:t2:3`, `upgrades:t2:2:1:r1`). In a wide arena a spawn's spot, the boss's seats, the summons' points, and the piles' spots depend on the view (the player's place and aim) as well as the stream, so a seed replays them only with the same movement; tier 1 is unchanged (its view covers the floor).
- Cheats: `scripts/cheats.gd` holds the code words typed into the title's seed field: `CODES` (a word to the run's flags) and `ACTIONS` (a title-time action, never a run flag: `tabula` is `"wipe"`, `actus2`/`actus3` are `"act:2"`/`"act:3"`, read by `Cheats.act_of`; `scalae` is `"tiers"`, `Cheats.TIERS_ACTION`: `Profile.unlock_all_tiers()`, every shipped tier unlocked and committed, no wipe and no backup, then Play as usual); a word is in one table or the other, and never a seed. `Cheats.parse(text)` is pure and gives `{"seed", "cheats", "action"}` (an action word: a random seed, no flags); the title emits `play_pressed(seed, cheats, action)` and `Main.play(seed, cheats, action)` runs a `"wipe"` through `Profile.wipe()` (the file copied to `<path>.bak` by `Save.back_up`, the Save replaced and committed; a failed copy wipes nothing) before it reads `flags.returned`; an act action wipes the same way, then `Story.apply_act(n)` writes that act's preset from `data/story/acts.json` (`StoryCatalog.acts`, validated at load: the profile's flags, the story flags, the events played) and commits (a failed copy or a missing preset applies nothing). `RunState.cheats` (set by `start_run`) is read by `Player.hurt` (`immortal`, `permawhat?`), `RunState.start_run` (`rich`, `dives`: `RICH_COINS`), and `VerdictRules.decide` (`thumbs_down`, `verso`); the gate screen, the run's record, and `RUN_END` say `cheats=<flags>` (`Cheats.describe`).
- Coins: `EnemyDef.coins` is an enemy's worth; `RunState.add_coins(value)` is the one writer of the run's coins and the one emitter of `coins_changed` (Main's `_pay` for a kill and the Cheer bonus, a `CoinPile` on contact, the sweep at a thumb up). A kill's coins fly to the HUD counter (`CoinFlight`, cosmetic, from the kill's point clamped to the screen: `Hud.flight_start`); a Roar's tally and the boss's coins (every body's, `Main._fight_coins`, thrown once where the fight's last body fell) are thrown as `CoinPile`s (`Main.throw_piles`, deferred) at `PileRules.spots` from the `piles:<round>` stream inside the floor ∩ `View.bare_rect(room).grow(PileRules.EDGE)` (on the screen; the floor itself in tier 1), under `Room/Piles` (they survive the picker), swept at a thumb up or lost at a down. A landed pile within `RunState.pull_radius` (`PileRules.PULL_RADIUS` 96 plus the Reach line) is pulled to the player (`CoinPile.PULL_SPEED`, `PULL_ACCEL`); throws land in a ring past the reach (`RING_MIN` 112 to `RING_MAX` 160).
- Favour: `FavourRules.ACTS` is the table of acts (chain, dare, daring, clean_round, hit); a round's kills share `KILL_BUDGET` (40) over `RunState.round_enemies` (`kill_share`; a summon pays nothing but counts for the chain, the daring, and the grace), scored as `KILL_ACT` through `apply_kill`; the boss's bodies pay it by damage over the fight's summed health (`boss_hit_share(damage, max_hp, paid)` with `Favour.fight_max_hp`: the larger of `RunState.round_boss_hp` and the bodies registered this round; the kill act under the gate, spent from `round_kill_paid`, up to `1 - BOSS_KILL_RESERVE` of the budget); the last body's kill the remainder (`boss_kill_share(enemies, paid, bodies, last)`: 0 for a body whose death leaves another standing; one body exactly `kill_share`); the table's acts through `apply(value, act, gate_open)`. `Favour` (a Node under Main, one detector per act) emits `favour_changed(value, band, act)` on `RunState.elapsed`, and scores nothing while the run is not live. A dash passing within `DANGER_RADIUS` of a harmful enemy (a charging body swept along its `Enemy.dare_velocity()` over the dash, through `dash_past_bolt`'s closest approach; every other body where it stands) or `BOLT_RADIUS` (20) of an enemy bolt (`dash_past_bolt`) scores one `dare`; a kill within `DASH_WINDOW` of its end scores `daring` too. The decay (`decay`, `DECAY_ACT`): after `DECAY_GRACE` (2 s) without a scoring act (`is_scoring`) while the run is live (`run_started` to `player_fell`, `run_won`, `run_ended`, or `grounds_entered`: `Favour.LIVE_ON`/`LIVE_OFF`, the one list, which the arrows connect too) and unpaused, `DECAY_PER_SECOND` (4); a shot landing on the boss (a loud `enemy_hit`; never a status tick, `Health.last_hit_quiet`) pays its share, so restarts the grace; a hit on any other enemy holds nothing off. ## Tests

- gdUnit4 with `report/godot/push_error=true`: a `push_error` during a test fails it. Autoloads are live in the runner.
- Scene tests wait on `get_tree().physics_frame` or on the Clock, never the OS clock, so a run is the same at fixed fps and in real time. `SceneSuite.real_seconds(t)` is a timer on the engine's unscaled step, used only for what is real time by design (hitstop, `Main.ROUND_GAP`, the verdict scene's `WIN_HOLD`, `WIN_SHOW`, `VERDICT_*`, `FADE_TIME`, `PICKER_DELAY`, `ENTRY_LINE_TIME`, `Audio.MUSIC_FADE`, the boss's `CORPSE_FLASH_HOLD`, `Fx.BOSS_DEATH_STAGE`); a test waiting for the next round uses `wait_for_round(main, index)`. `wall_msec(ms)` is the one wait on the OS clock (blocking), for the mixer's thread only.
- Every scene test extends `SceneSuite` (`tests/support/scene_suite.gd`) and builds Main with `quiet_main()` or `quiet_main_with_series()` (the title off, `Room/WaveRunner` disabled); a test in the grounds calls `main.enter_grounds()` on a quiet Main. `before_test` resets `Juice` (the last test's scene can still start a hitstop after its `after_test`), points `Profile.path` at `PROFILE_SCRATCH`, and puts `Story` on the empty fixture; `after_test` awaits a frame (so a node freed in the last line is no orphan), then resets `Juice`, removes `PROFILE_SCRATCH` and `SETTINGS_SCRATCH` (per-process `static var`s) and resets the profile, then `RunState` (`tier` and `run_tier` back to 1, then `start_run`, which reads the profile's training ranks, so the profile goes first) and `Audio`; an override calls `await super()`. A pure suite uses its own scratch path and never touches `Profile`. Never add a second `RunState` to the tree. Helpers: `stand_at(main, id)` (an area pairs two or three ticks after a placement: wait with `wait_until`, never a bare tick count), `interact()`, `press_action(action)` (an `InputEventAction` through `Input.parse_input_event`; `Input.action_press` never reaches an `_unhandled_input`), `through_box`, `go_through`, `take_the_lift(main, tier := 1)`, `pass_the_gate` (the gate screen), `fall_to_the_gate`, `clear_and_pick` (never a Switch or the locked card), `plays(name)`, `click_control`/`click_at(window_position)`, `hover_control`/`hover_at` (end a hovering test with `hover_at(Vector2.ZERO)`; a mouse event goes through `get_viewport().get_final_transform()`, the headless window being 64x64). M7's: `wide_series(rounds)` (56x30, one chaser a round), `boss_series`, `pair_series()` (one wave of two tier 1 bosses), `active_charger_on`/`active_bearer_on` and `active_boss_on(main, at, stationary, scene_path)` (stationary: the walk's speed 0; the charge and the banner the def's), `take_the_lift(main, tier)`; `Main.user_args` (a static, the command line's user args by default) and `Main._args_applied` are the seam for `--seed`/`--tier` (a test saves and restores both). A test in a wide arena finds enemies by the group `enemies`, never by a container's children.
- Tests never depend on the shipped prose: `before_test` puts `Story` on `tests/support/story_empty/`; a story suite calls `use_story("res://tests/support/story")` (or `tests/support/story_arrival/` for `arrival`). Only `tests/test_story_data.gd` reads `data/story/`, asserting validity and a clean lint, never a sentence (and `test_story_write.gd`'s shipped case, asserting the files' canonical form); a test of the crowd's or the narrator's pool checks the picked event's shape, never its id. The writer's-kit suites write their stories into a per-process `user://` scratch (`story_edit_<pid>`, `story_tab_<pid>`, `story_session_<pid>`, `story_whatif_*_<pid>.cfg`), removed after each test; `test_story_tab.gd` runs the tab's scene outside the editor (signals through the handlers they are connected to, `pointer` the drag's seam), `test_story_session.gd` and `test_story_whatif.gd` the rules without it. A test never depends on a gitignored asset: it overrides the stream with a generated one (as `test_audio.gd` does).
- Follow TDD: write the failing test, run it, implement, run again. During TDD run the touched suites (`-a`); run the full suite once before committing. A second run only for a change that draws from `RunState.rng` or a seeded stream in a test that does not seed it (`after_test` reseeds from `randi()`). A change that touches the clock itself (`Clock`, a real-time wait's helper, what reads the Clock) also runs `tools/test.sh --realtime` once by hand.

## Process

- A new plan names the files, the behaviour, and the tests, with short snippets where the shape matters; it does not paste whole files.
- One agent in the checkout at a time: implementers, reviewers, and the coordinator share one working tree, so a coordinator commit made while an implementer works uses explicit paths (`git commit -- <files>`), never `git add -A` (it sweeps the implementer's edits into the wrong commit). Reviews are read-only. Two test runners on one machine are safe: the scratch profile, the settings scratch, and the test log are per process.
- The build loop per task: an implementer, a spec-compliance review, a code-quality review, one fix pass, a re-review. A small tuning task may take one combined review. An agent cut off by a usage limit is resumed with `SendMessage` (check `git status` first).
- Milestones close only on the user's playtest verdict. Keep the plan document in sync with every deviation from it.
- Show, don't tell (the colosseum design): no caption, hint, tutorial, label, or character line explains a mechanic or addresses the player. UI may name, never narrate: a thing may carry its name (the post's rows, the pause screen's tabs, "Pick a boon") and a hovered line may say what it buys, but nothing says how a system works; a meter has no name, the gate screen names the gate. Text may reinforce, never explain: a line in the world's voice that reinforces a feeling the player already has is in (the crowd's judgement at the pick, the narrator at the verdict); a line that breaks the fourth wall, infodumps, or says how a system works is out. Every spec-compliance review checks this as a spec item, and `docs/TESTERS.md` may name a mechanic in a question but never explain one.
- Do not downgrade silently when a step needs the user (downloads, logins): put it in the plan as a user action and work around it.
