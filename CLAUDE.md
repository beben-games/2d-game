## Commands

- `tools/test.sh` runs every gdUnit4 suite headless; exit 0 pass, 100 failures, 105 script errors, 1 if no tests found. `tools/test.sh -a res://tests/<file>.gd` runs one suite. It prints a digest (each failed test with its report, script errors, the summary line); the full output is in `reports/test.log`, and `-v` streams it. Read the log only when the digest is not enough.
- `tools/check_boot.sh` boots the main scene headless and fails on any `ERROR:`/`WARNING:` line. Godot exits 0 even when the main scene fails to load, so never use its exit code alone.
- `tools/smoke.sh [idle|move|combat|kill|round|fall|pick|title|pause|boss|grounds]` opens a window for a few seconds, drives input in physics ticks, and writes `reports/smoke_<scenario>.png` plus `SMOKE_` lines. `kill`, `round`, `fall`, and `pick` assert on their key line; `round`, `fall`, and `pick` run on `tools/smoke_series.tres` (two rounds of one chaser). `round` takes card 1 and waits the gap (`SMOKE_ROUND 1`); `fall` kills the player beside a chaser, saves `reports/smoke_fall_verdict.png` at the thumb (`SMOKE_VERDICT up`) and ends on the gate screen (`SMOKE_GATE Porta Triumphalis`; the end capture is the screen over the black, dark by design); `pick` also saves `reports/smoke_pick_menu.png` with the cards up; `title` saves the paused front door as `reports/smoke_title_screen.png` before Play and `pause` the pause screen as `reports/smoke_pause_menu.png` (the unconditional end capture `smoke_<scenario>.png` is the run after); `boss` runs on `tools/smoke_boss_series.tres`, shoots the boss until its first ring, and asserts `SMOKE_BOSS_HP n of 600` below max under a visible bar; `grounds` sets `flags.returned` on its scratch profile, plays into the grounds, walks the player left into the post, and asserts `SMOKE_GROUNDS post` (the end capture has the training panel up). Every scenario fails if it ran silent (`SMOKE_AUDIO 0`). A 30 s in-process watchdog; smoke.sh reports `watchdog: scenario hung`. Read the PNG to verify visuals. The smoke tool and the reload probe point `Profile.path` at their own scratch (`user://smoke_profile.cfg`, `user://probe_profile.cfg`) so no tool ever writes the player's save.
- `tools/release.sh [version]` publishes the built zips as the GitHub release `v<version>` of https://github.com/beben-games/2d-game (a `-rc` version is a pre-release; needs `gh auth login` and the commit pushed).
- `tools/run.sh [--seed=N]` plays the game from the project with the Godot binary; the user's way to run locally.
- `tools/build.sh [version]` exports the tester zips (Windows x64 and Linux x64, release, `export_presets.cfg`, `docs/TESTERS.md` as the README) into `builds/` (gitignored). Needs the 4.7.2 export templates installed in the editor. The version comes from `config/version` in `project.godot`.
- `tools/gen_atlas.py` regenerates `data/atlas.json` from the tileset's tile list. Sprites are always looked up by name through `SpriteAtlas`; never hardcode atlas pixel coordinates.
- `tools/gen_icons.py` regenerates `data/icons.json` (card and HUD icons by name, from a (row, col) table on the Raven sheet). Headless Godot generators, run as `source tools/godot.sh && perl -e 'alarm 120; exec @ARGV' "$GODOT_BIN" --headless --path . -s tools/<script>.gd </dev/null`: `gen_guns.gd` (the handgun sprite from the user's pistol sheet), `icon_sheet.gd` (renders every icon to `reports/icons.png` for a check by eye).
- Godot binary: `source tools/godot.sh` exports `GODOT_BIN` (/Applications/Godot.app/Contents/MacOS/Godot, 4.7.2).

## Conventions

- Commits: no global git identity on this machine. Use `git -c user.name="Benjamin Zigh" -c user.email="78459259+beben-games@users.noreply.github.com" commit` and end messages with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- The repo is public at https://github.com/beben-games/2d-game (`origin`), code MIT (`LICENSE`), assets per `CREDITS.md`. Packs whose terms forbid reposting (Raven icons, the pistol sheet, the Minifantasy and Classic Monster sounds, both music loops, the reserve sets) are gitignored and never committed: they live in the working copy and ship only inside the builds (`docs/ASSETS.md`). A new asset gets a `CREDITS.md` row with its license and an "In the repo" verdict before it is committed. Without them `IconAtlas` draws a placeholder (`ICON_MISSING`) and `Audio` plays silence.
- Commit Godot's generated `.uid` and `.import` files. `reports/` and `.godot/` are ignored. Never edit `addons/gdUnit4` (vendored upstream v6.2.1).
- The login shell is zsh; tool scripts are bash and are executed, never sourced.
- Physics layers: 1 player, 2 enemies, 3 player_shots, 4 enemy_shots, 5 walls (bit values 1, 2, 4, 8, 16), 6 pickups (bit 32): the coin pile (`scenes/coin_pile.tscn`, an `Area2D` masking 65 with monitoring off until its toss lands), 7 player_dashing (bit 64): the player's body layer during a dash; enemies never mask it (a trigger that must see a dashing player masks 65, as the pile and the grounds' stations do). Player body mask is 18 (walls, enemies), or 16 (walls only) while dashing; enemy bodies 19 (walls, enemies, player). Player shots mask 2 (enemies only) and enemy bolts mask 0; walls are handled by the projectile's raycast against layer 5 (`Projectile.WALL_MASK`). Enemy bodies are solid; damage reaches the player only through the hurtbox. A shielded enemy (`EnemyDef.shield`) blocks a player shot arriving inside its front arc through `Enemy.blocks_shot(direction, pierce)`, which `Projectile._on_body_entered` asks duck-typed before `take_damage`, unless the shot's pierce is at least `Enemy.SHIELD_PIERCE` (3); the rules are `ShieldRules`, the facing follows the enemy's movement at `shield_turn_degrees` a second and holds under a stun. The boss (`scenes/enemies/boss.tscn`) is an enemy body too (layer 2, mask 19) in the group `boss`; only a `StaticBody2D` (a wall) ends its charge; its summons carry the group `summoned`, which `WaveRunner` ignores.
- Randomness: shot spread and the shooter's recover jitter (`Enemy.RECOVER_JITTER`) use `RunState.rng`; systems whose placement must depend only on seed and time use `RunState.stream(name)`; cosmetic effects use the global RNG; the arena floor derives its own RNG from the seed.
- Cheats: `scripts/cheats.gd` is the one table of code words (typed into the title's seed field; `Cheats.parse(text)` is pure and gives the seed and the flags; a code word is never a seed). `RunState.cheats` holds the run's flags, set by `start_run(seed, cheats)` and empty otherwise; the readers are `Player.hurt` (`immortal`, `permawhat?`), `RunState.start_run` (`rich`, `dives`: the run starts with `RICH_COINS`), and `VerdictRules.decide` (`thumbs_down`, `verso`: the thumb turns down); the gate screen's run block, the run's record, and the `RUN_END` print say `cheats=<flags>` (`Cheats.describe`) so a cheated run is never mistaken for a real one.
- Coins: `EnemyDef.coins` is the enemy's worth; `RunState.add_coins(value)` is the one writer of the run's coins and the one emitter of `coins_changed` (Main's `_pay` for a kill and the Cheer bonus, a `CoinPile` on contact, the sweep at a thumb up). A kill's coins fly to the HUD counter as a cosmetic `CoinFlight`; a Roar's tally and the boss's coins are thrown as `CoinPile`s (`Main.throw_piles`, deferred: a pile is a physics body) at `PileRules.spots` drawn from the round's `piles:<round>` stream; piles live under `Room/Piles`, survive the picker, and are swept into the counter at a thumb up or lost at a thumb down. A landed pile within `RunState.pull_radius` (`PileRules.PULL_RADIUS` 96 at `start_run`; a training line widens it later) is pulled to the player each physics tick (`CoinPile.PULL_SPEED`, `PULL_ACCEL`; the player found once at `land()` through the `player` group); every throw lands in a ring past the reach (`PileRules.RING_MIN` 112 to `RING_MAX` 160, clamped inside the floor, on the open side near a wall), so the piles wait to be walked to.
- Favour: `FavourRules.ACTS` is the one table of acts and their values; `Favour` (a `Node` under Main) holds one detector per act on the bus and scores through `FavourRules.apply`, emitting `favour_changed(value, band, act)`; its clock is `RunState.elapsed` (never wall time). Main emits `round_ended(band)` at every round's end (the crowd's sound, `Audio.CROWD_SOUNDS`), and the band picks the granter and the card count (`FavourRules.granter`, `offer_count`). The meter has no label: the crowd's sound is its explanation.
- The stage: Main holds exactly one of the `Room` (the arena) and the `Grounds` (`scenes/grounds.tscn`) at child index 0, swapped by `enter_arena()` and `enter_grounds()` (never inside a physics callback: both hold physics nodes); `main.room` or `main.grounds` is null for the one not up. The grounds are the arena's tiles ringed solid with three `Station` `Area2D`s made in code from `ArenaGrid` (`post` a crate with a spear, left third; `rack` three weapons on the top wall's face, right third; `gate` the open door where the emperor's box stands): walking in raises `station_entered(id)`, which opens the `TrainingPanel` or the `ArmouryPanel` (CanvasLayers 10 under Main, not paused, closed on `station_exited`) or, for the gate, fades to black, `enter_arena()`, and starts the run. No run is live in the grounds (the HUD hidden, `RunState` untouched, `Player.can_fire` off so no shot leaves the body, the profile counting no shot or dash there but `time_in_grounds`, the pause screen's Restart hidden through `set_restart_visible`; R and Restart do nothing there, Quit to title yields nothing). The stage swap is `Main._mount_stage(stage)`: the old stage freed, the new at index 0, the player at its `entry_position()` with its `Projectiles` node (none in the grounds) as the shots' parent, the camera on its `full_rect()`. The first-run rule: `Main.play()` starts in the arena while `Profile.save.flags.returned` is false; the gate screen's continue (`_pass_gate`) enters the grounds and sets the flag (`Save.set_flag`, committed), so every later Play lands in the grounds with the title's seed and cheats kept for the gate (`_pending_seed`, used once). `Player.revive()` makes the body whole (on `run_started`, and at `enter_grounds`); the HUD re-reads the player on `run_started`. `_pending_seed`/`_pending_cheats` are cleared by `_forget_run` (a run's start, a restart, a quit from the grounds).
- Training: `TrainingRules.LINES` is the one table (hearts, breath, renown: ranks and prices); `TrainingRules.buy(save, line)` is the purchase (money, rank, `coins_spent`), the panel commits and emits `training_bought` or `purchase_denied` (the sounds `buy`/`buy_denied`). `Build.starting(save)` sets `base_max_hp`/`base_dash_charges` from `TrainingRules.apply(save)` and `RunState.start_run` builds from `Profile.save` and sets the favour from the same; the player cards fold over the bases. Music: `music_run` from `round_started(0, _)` (and the title), `music_boss` from the boss's spawn, `music_grounds` from `grounds_entered`.
- `Events` is the signal bus; nodes that connect to it disconnect in `_exit_tree`. `Player.hurt()` is the only way to damage the player.
- Signals live in `scripts/autoload/events.gd`. Lifetime rule: `round_cleared` and `enemy_died` arrive from inside physics callbacks (a shot's `body_entered`), so a handler that adds or removes physics nodes, or pauses the tree, must defer (`call_deferred`, or emit deferred) or wait a real-time timer (`Main._offer_upgrade_later` and `_next_round_later`), or Godot fails with "can't change this state while flushing queries". `upgrade_chosen(card, rank)` carries rank 0 for Heal and Switch cards.
- Pausing: the upgrade menu, the build screen (`BuildScreen` is the pause screen: Tab or Esc, the `pause` action, with the options column of Resume, Restart, the three volume sliders, Quit to title, and Quit game), the gate screen (`GateScreen`, layer 30: Enter or a click continues, R restarts, Esc returns to the title), and the title (`Title`, layer 15, the front door with Play, the seed field, and Quit) set `get_tree().paused`; they are CanvasLayers with `process_mode` ALWAYS (the menus on layer 10, the title on 15). Main boots into the title paused; `quiet_main()` and the smoke tool set `start_at_title` false. Anything that must run under them (input, timers) lives in those nodes. `Main.restart` and `SceneSuite.after_test` unpause. Call `Juice.reset()` before pausing so a kill freeze's time scale does not survive under the menu. `Title` and `BuildScreen` emit `quit_requested`, which Main connects to `get_tree().quit`; a test disconnects that before pressing a Quit button and counts the signal instead.
- Weapons are never mutated: the player fires `RunState.build.resolve(...)`, re-resolved on `build_changed`. New weapon stats are Modifier stat names too (`Modifier.WEAPON_STATS`); adding content means adding a `data/upgrades/*.tres` or `data/weapons/*.tres` file, which `UpgradeCatalog` validates at load.
- Icons and UI: card and HUD icons are looked up by name through `IconAtlas` (`IconAtlas.rect(name, scale)` for a container-sized icon, `SpriteAtlas.rect(name, scale)` for a tileset sprite the same way: the coin on the HUD's counter and the training rows) (`data/icons.json`, generated by `tools/gen_icons.py` from a (row, col) table on the Raven sheet); frames and panels come from `UiTheme` (`assets/dungeon_ui`) and the fonts from `assets/fonts` (TrueType pixel fonts on a 16 px grid, imported without antialiasing or hinting; font sizes are multiples of 16 so the glyphs land on whole pixels). Never hardcode a sheet coordinate outside those tools.
- Audio: every sound is a name in `data/audio.json` played by the `Audio` autoload on a bus signal; gameplay code never touches a player. A missing file is silence plus an `AUDIO_MISSING` line (`check_boot.sh` counts them). `Engine.time_scale` does not pitch audio in Godot 4, so nothing compensates for hitstop. `Audio.reset()` runs in `SceneSuite.after_test`; `Audio.plays` counts plays by name for tests and the smoke tool. `audio.gd` never names a gameplay Node class (`Health`, `Enemy`, `Player`, ...) statically; it duck-types through `get()` and `get_node_or_null`; `check_boot` catches a regression as leaked ObjectDB instances at exit. A sound that must outlive a pause that follows it within a second (the crowd's `crowd_boo|quiet|cheer|roar` at a round's end before the picker, `crowd_hush`, `player_die`, `verdict_up|down`, `gate`) plays on the UI pool (`Audio.play_ui`), which the pause does not freeze; the coin sounds (`coin_get` on a flight's landing, `coin_toss`, `coin_pickup`) and the grounds' `buy`/`buy_denied` play on the game pool. The loops are `music_run`, `music_boss`, `music_grounds`.
- Profile: `Profile` (autoload after `Audio`) holds one `Save` (`scripts/save.gd`: money, training ranks, flags, every stat in `Save.STAT_KEYS`, the run log) loaded from `Profile.path` (`user://save.cfg`) at boot and filled by the bus (one handler per signal, connected in `_ready`, disconnected in `_exit_tree`); `Profile.commit()` is the only write to disk (the verdict, the purchases, and the first gate-screen pass call it), never a listener. A file the game cannot read (corrupt, or a later `version`) is copied to `<path>.bak` before the defaults load. Every tool and test points `Profile.path` at its own scratch (`SceneSuite.PROFILE_SCRATCH`, `user://smoke_profile.cfg`, `user://probe_profile.cfg`) so nothing but the game ever writes the player's `user://save.cfg`. A new stat is a `STAT_KEYS` row (plus `PER_ID_KEYS` when nested by id); an older file loads it at its default, a file from a later version loads as defaults. `player_hit` and `player_fell` carry `attacker_id` (the enemy's def id or the bolt's `shooter_id`, "" unknown; the profile files "" under `Save.UNKNOWN_ID`). Tests: `SceneSuite.before_test` points `Profile.path` at `PROFILE_SCRATCH` and resets, `after_test` removes the scratch and resets again (a suite that overrides either calls `super()`); a pure suite uses its own scratch path and never touches `Profile`.
- The fall and the verdict: `Player.hurt` at 0 hp calls `_fall` (the sprite laid flat, `dead` true, `player_fell(position, attacker_id)`); Main's `_on_player_fell` turns the runner off and, after `VERDICT_HOLD`, `_verdict(false)`; `_win` emits `run_won` (Audio: the fanfare `verdict_up`, the loop stopped) and after `WIN_HOLD` `_verdict(true)`. On a fall `_verdict` asks `VerdictRules.decide(band, hits_taken, flags, cheats)` (pure; UP unless `thumbs_down` until M9), shows the `ThumbSign` over the box (a Room child) and emits `verdict_given(up)` (Audio: `verdict_up`/`verdict_down`); a win asks no emperor (no thumb, no `verdict_given`, always UP). Either way it sweeps the floor's piles on an UP, banks and records the run (`_bank`: money and `coins_earned` on UP, `coins_lost` plus `deaths`/`deaths_by` on DOWN, `runs`, `wins`/`falls`, `perfect_runs`, `best_run`, `boss_time_best`, `log_run`, `Profile.commit()`, `run_ended("win"|"fall")`), prints `RUN_END ...`, waits `VERDICT_SHOW` (the sweep's flights land), fades to black (`FADE_TIME`), and opens the `GateScreen` (`show_gate(up, record, save)`; the title is `VerdictRules.gate_name`). `restart()` mid-run (R, Restart, Quit to title, and `quit_to_title`) is a yield: `run_ended("yield")`, the coins to `coins_lost`, a run and a fall counted, the record logged with an empty verdict, `commit()`; guarded on `_ended` and the title. The verdict scene cannot be skipped: `restart()` and `quit_to_title()` return while `_verdict_pending()` (the run ended, the gate screen not yet open), so a run is recorded exactly once. The verdict scene's times are real time by design.
- Headless generator scripts (`tools/gen_*.gd`, `tools/icon_sheet.gd`) run with `-s` and must `quit()` on every path; a failed `assert` hangs the process, so they report with `push_error` and `quit(1)`. Run them under `perl -e 'alarm 120; exec @ARGV'`.
- Arena geometry: a run is a `SeriesDef` (`data/series/tier_1.tres`: the arena size and eight `RoundDef`s, each a `WaveTable`) fought in one `Room` that lives for the run; Main's `_enter_round` hands the runner the next table after the pick and a real-time `ROUND_GAP`. The arena is 28x15 tiles of 16 px (448x240, one screen at 3x zoom), walls solid on every side. The top wall is two rows (ledge over face) with the emperor's box (`EmperorBox`, the tileset's closed door sprites) set into it at x 208..240; side and bottom walls are one row; the floor is 26x12 (`ArenaGrid.bounds`). All of it derives from `ArenaGrid`; never hardcode an arena coordinate. CanvasLayer order: HUD 1, UpgradeMenu and BuildScreen 10 (never shown together), Title 15, Fade 20, GateScreen 30.
- Feel constants live next to what they affect (`juice.gd`, top of `enemy.gd` and `player.gd`, `dash_rules.gd`, `status_effects.gd`, `projectile.gd` for homing, the wall nudge, `BOLT_SCALE`, and the status trails (`TRAIL_*`, `TRAIL_STACK_GAP`), `camera.gd`, the verdict scene's holds, the fade, `ROUND_GAP`, and `PILE_WAIT_CAP` (after the gap the next round waits for the floor's piles up to it, on a timer that pauses with the tree) in `main.gd`, the thumb's scale in `thumb_sign.gd` (the sign is the Raven sheet's `thumb_up`/`thumb_down`), the piles' counts, ring, and spacing in `pile_rules.gd`, the toss and the flight at the top of `coin_pile.gd` and `ui/coin_flight.gd`, the counter's place in `ui/hud.gd`, the card and panel sizes at the top of `ui/upgrade_menu.gd`, `ui/build_screen.gd`, `ui/training_panel.gd`, and `ui/armoury_panel.gd`, the stations' art and margins at the top of `grounds.gd`); the rules tables in `favour_rules.gd`, `pile_rules.gd`, `training_rules.gd`, and `verdict_rules.gd`); data lives in `data/*.tres` (enemies, weapons, upgrades, waves, rounds, series).

## Tests

- gdUnit4 with `report/godot/push_error=true`: a `push_error` during a test fails it. Autoloads are live in the runner.
- Scene tests wait on `get_tree().physics_frame`, not wall-clock, so timings are machine-independent. Real-time waits are only for what is real time by design: hitstop, the round gap (`Main.ROUND_GAP`), the verdict scene (`Main.WIN_HOLD`, `VERDICT_HOLD`, `VERDICT_SHOW`, `FADE_TIME`), the picker delay (`Main.PICKER_DELAY`), the music crossfade (`Audio.MUSIC_FADE`), the boss's `CORPSE_FLASH_HOLD`, and `Fx.BOSS_DEATH_STAGE`.
- Every scene test extends `SceneSuite` (`tests/support/scene_suite.gd`) and builds Main with `quiet_main()` or `quiet_main_with_series()`, which set `start_at_title` false and disable `Room/WaveRunner` so nothing spawns on its own (the one `Room` lives for the run, so the runner stays off unless a test turns it on). The base `after_test` resets `Juice` and `RunState`; a suite that overrides it must call `super()`. Never add a second `RunState` to the tree. A test in the grounds calls `main.enter_grounds()` on a quiet Main and waits on the station's pairing with `wait_until` (two or three ticks after a placement), never a bare `ticks(2)`; `SceneSuite` also has `plays(name)`, `fall_to_the_gate(main)`, `pass_the_gate(main)`, and `click_control(control)` (a mouse event for a Control goes through `get_viewport().get_final_transform()`: the headless runner's window is 64x64, scaled; an event fed by `Input.parse_input_event` is delivered at the next frame's flush). The base `after_test` awaits a frame first so a node freed in a test's last line is not counted as an orphan: an override must `await super()`.
- Follow TDD: write the failing test, run it, implement, run again. During TDD run the touched suites (`-a`); run the full suite once before committing. Run it a second time only when the change can make a test flaky: a scene test added or changed, a timing constant or a real-time wait touched, or code that draws from `RunState.rng` or a seeded stream (a test can pass once on a lucky seed or a lucky tick).

## Process

- A new plan names the files, the behaviour, and the tests, with short snippets where the shape matters; it does not paste whole files (git holds the code, and long plans cost every reader).
- Milestones close only on the user's playtest verdict. Keep the plan document in sync with every deviation from it.
- Show, don't tell (the colosseum design): no caption, hint, tutorial, label, or character line explains a mechanic, names a system, or addresses the player; a panel shows its objects, a meter has no name, the gate screen names the gate. Every spec-compliance review checks this as a spec item, and the tester file (`docs/TESTERS.md`) may name a mechanic in a question but never explain one.
- Do not downgrade silently when a step needs the user (downloads, logins): put it in the plan as a user action and work around it.
