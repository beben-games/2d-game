## Commands

- `tools/test.sh` runs every gdUnit4 suite headless; exit 0 pass, 100 failures, 105 script errors, 1 if no tests found. `tools/test.sh -a res://tests/<file>.gd` runs one suite. The engine runs at `--fixed-fps 60` by default (a 1/60 s step a loop iteration, never waiting on the wall clock); `--realtime` paces it on the wall clock as the game is; `-v` streams the full output; both flags come before `-a` (a flag after `-a` is refused, before the import step). It prints a digest (each failed test with its report, script errors, the summary line) from its own `reports/test_<pid>.log`, moved to `reports/test.log` at exit (with two runners, the last to finish owns it). Read the log only when the digest is not enough.
- `tools/check_boot.sh` boots the main scene headless and fails on any `ERROR:`/`WARNING:` line, then runs the reload probe (`tools/reload_probe.gd` under `--fixed-fps 60`: Play, Restart, a fall to the gate screen, the grounds, Quit to title, the Ludus's top door, the lift, a yield; `RELOAD_PROBE ok`). Godot exits 0 even when the main scene fails to load, so never use its exit code alone.
- `tools/smoke.sh [idle|move|combat|kill|round|fall|wake|pick|roar|boo|title|pause|boss|grounds|rooms|talk]` opens a window for a few seconds, drives input in physics ticks, and writes `reports/smoke_<scenario>.png` plus `SMOKE_` lines; all but `idle`, `move`, and `combat` assert their key lines. `round`, `fall`, `wake`, `pick`, `roar`, and `boo` run on `tools/smoke_series.tres` (two rounds of one chaser), `boss` on `tools/smoke_boss_series.tres`; `grounds`, `rooms`, and `talk` set `flags.returned` on the scratch profile and Play into the Ludus. Asserted lines and extra captures: `kill` `SMOKE_KILLS 1`; `round` `SMOKE_ROUND 1`; `fall` `SMOKE_VERDICT up`, `SMOKE_NARRATOR verdict_up`, `SMOKE_GATE Porta Triumphalis` (`smoke_fall_verdict.png` at the thumb; the end capture is the gate screen over the black, dark by design); `wake` (`verso`) `SMOKE_GATE Porta Libitinaria`, `SMOKE_WAKE spoliarium prone=true`, `SMOKE_ROSE true` (`smoke_wake_prone.png`; `SMOKE_WAKE_LINE` unasserted); `pick` `SMOKE_MENU_OPEN true`, `SMOKE_CROWD_LINE crowd.<name>`, `SMOKE_UPGRADE <id>` (`smoke_pick_menu.png`); `roar` (at `FavourRules.MAX`) `SMOKE_ROAR 4`, `SMOKE_CROWD_ROARS 2` (`smoke_roar_menu.png`); `boo` (at a Boo) the crowd's line and `SMOKE_BOO_LOCKED <index>` (`smoke_boo_menu.png`); `title` `SMOKE_TITLE played=true paused=false` (`smoke_title_screen.png`); `pause` `SMOKE_PAUSE open=true paused=true` (`smoke_pause_menu.png`); `boss` `SMOKE_BOSS_HP n of 600` below max, `SMOKE_BOSS_BAR true`; `grounds` `SMOKE_ARRIVAL <pool>.<name> open=true`, `SMOKE_GROUNDS_WORD lanista.<name>`, `SMOKE_GROUNDS post` (`smoke_arrival.png`, `smoke_grounds_key.png`; the end capture has the training panel up); `rooms` `SMOKE_ROOMS ludus armamentarium sanitarium hypogeum spoliarium` (`smoke_room_<id>.png`, `smoke_room_door_key.png`); `talk` `SMOKE_TALK veteran.<name> open=false` (`smoke_talk_mark.png`, `smoke_talk_key.png`, `smoke_talk_box.png`, `smoke_talk_choices.png`). The story's checks match a pool and a shape, never an event's name. Every scenario fails if it ran silent (`SMOKE_AUDIO 0`). A 30 s in-process watchdog (`watchdog: scenario hung`). Read the PNGs to verify visuals. The smoke tool and the reload probe use their own per-process scratch profiles (`user://smoke_profile_<pid>.cfg`, `user://probe_profile_<pid>.cfg`), never the player's save.
- `tools/release.sh [version]` publishes the built zips as the GitHub release `v<version>` of https://github.com/beben-games/2d-game (a `-rc` version is a pre-release; needs `gh auth login` and the commit pushed).
- `tools/run.sh [--seed=N]` plays the game from the project with the Godot binary; the user's way to run locally.
- `tools/build.sh [version]` exports the tester zips (Windows x64 and Linux x64, release, `export_presets.cfg`, `docs/TESTERS.md` as the README) into `builds/` (gitignored). Needs the 4.7.2 export templates. The version comes from `config/version` in `project.godot`.
- `tools/gen_atlas.py` regenerates `data/atlas.json` from the tileset's tile list. Sprites are always looked up by name through `SpriteAtlas`; never hardcode atlas pixel coordinates.
- `tools/gen_icons.py` regenerates `data/icons.json` (icons by name from a (row, col) table on the Raven sheet). Headless Godot generators run as `source tools/godot.sh && perl -e 'alarm 120; exec @ARGV' "$GODOT_BIN" --headless --path . -s tools/<script>.gd </dev/null`: `gen_guns.gd` (the handgun sprite), `icon_sheet.gd` (every icon to `reports/icons.png`).
- Art tools (Python, `tools/art/`): `budget.py` prints what an art session may spend (`--left N` offline); `pixellab.py balance` is the REST client's check. The API key is read from the macOS login keychain (`tools/art/keys.py`, service `pixellab-api-key`) and never printed, logged, or written; `git config core.hooksPath tools/hooks` enables the pre-commit hook that refuses a staged key or `.env`.
- Godot binary: `source tools/godot.sh` exports `GODOT_BIN` (/Applications/Godot.app/Contents/MacOS/Godot, 4.7.2).

## Conventions

- Commits: no global git identity on this machine. Use `git -c user.name="Benjamin Zigh" -c user.email="78459259+beben-games@users.noreply.github.com" commit` and end messages with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- The repo is public at https://github.com/beben-games/2d-game (`origin`), code MIT (`LICENSE`), assets per `CREDITS.md`. Packs whose terms forbid reposting (Raven icons, the pistol sheet, the Minifantasy and Classic Monster sounds, the music loops, the reserve sets) are gitignored and never committed; they ship only inside the builds (`docs/ASSETS.md`). A new asset gets a `CREDITS.md` row with its license and an "In the repo" verdict before it is committed. Without them `IconAtlas` draws a placeholder (`ICON_MISSING`) and `Audio` plays silence.
- Commit Godot's generated `.uid` and `.import` files. `reports/` and `.godot/` are ignored. Never edit `addons/gdUnit4` (vendored upstream v6.2.1).
- The login shell is zsh; tool scripts are bash and are executed, never sourced.
- Physics layers: 1 player, 2 enemies, 3 player_shots, 4 enemy_shots, 5 walls (bits 1, 2, 4, 8, 16), 6 pickups (32: the coin pile, an `Area2D` masking 65, monitoring off until its toss lands), 7 player_dashing (64: the player's body layer during a dash; enemies never mask it, and a trigger that must see a dashing player masks 65, as the pile and every `Interactable` do). Player body mask 18 (walls, enemies), 16 while dashing; enemy bodies 19. Player shots mask 2 and enemy bolts 0; walls are the projectile's raycast against layer 5 (`Projectile.WALL_MASK`). Enemy bodies are solid; damage reaches the player only through the hurtbox. An enemy bolt carries `Projectile.ENEMY_BOLT_GROUP` from `scenes/enemies/enemy_bolt.tscn` itself (its motion `Projectile.velocity()`). A door's blocker and a cast member's lower body are `StaticBody2D`s on the walls' layer. A shielded enemy (`EnemyDef.shield`) blocks a player shot inside its front arc through `Enemy.blocks_shot(direction, pierce)`, asked duck-typed by `Projectile._on_body_entered` before `take_damage`, unless the shot's pierce is at least `Enemy.SHIELD_PIERCE` (3); the rules are `ShieldRules`. The shield's facing follows the enemy's movement at `shield_turn_degrees` a second and holds under a stun. The boss (`scenes/enemies/boss.tscn`) is an enemy body (layer 2, mask 19) in the group `boss`; only a `StaticBody2D` ends its charge; its summons carry the group `summoned`, which `WaveRunner` ignores.
- Time: game code under `scripts/` times by `Clock.now_usec()` (the first autoload: the engine's unscaled step, the clock every `create_timer(t, true, false, true)` runs on; wall time in the game, 1/60 s a frame under `--fixed-fps`), never `Time.get_ticks_*`: Juice's trauma decay and hitstop end, Audio's `min_gap`, and the text box's reveal read it; the one exception is Audio's release loop at quit (the mixer's thread). Tools keep real time. `Clock` reads 0 before its `_ready`, so no autoload reads it in an initializer.
- Randomness: shot spread and the shooter's recover jitter use `RunState.rng`; placement that must depend only on seed and time uses `RunState.stream(name)`; cosmetic effects use the global RNG; the arena floor derives its own RNG from the seed.
- Cheats: `scripts/cheats.gd` holds the code words typed into the title's seed field: `CODES` (a word to the run's flags) and `ACTIONS` (a title-time action, never a run flag: `tabula` is `"wipe"`); a word is in one table or the other, and never a seed. `Cheats.parse(text)` is pure and gives `{"seed", "cheats", "action"}` (an action word: a random seed, no flags); the title emits `play_pressed(seed, cheats, action)` and `Main.play(seed, cheats, action)` runs a `"wipe"` through `Profile.wipe()` (the file copied to `<path>.bak` by `Save.back_up`, the Save replaced and committed; a failed copy wipes nothing) before it reads `flags.returned`. `RunState.cheats` (set by `start_run`) is read by `Player.hurt` (`immortal`, `permawhat?`), `RunState.start_run` (`rich`, `dives`: `RICH_COINS`), and `VerdictRules.decide` (`thumbs_down`, `verso`); the gate screen, the run's record, and `RUN_END` say `cheats=<flags>` (`Cheats.describe`).
- Coins: `EnemyDef.coins` is an enemy's worth; `RunState.add_coins(value)` is the one writer of the run's coins and the one emitter of `coins_changed` (Main's `_pay` for a kill and the Cheer bonus, a `CoinPile` on contact, the sweep at a thumb up). A kill's coins fly to the HUD counter (`CoinFlight`, cosmetic); a Roar's tally and the boss's coins are thrown as `CoinPile`s (`Main.throw_piles`, deferred) at `PileRules.spots` from the `piles:<round>` stream, under `Room/Piles` (they survive the picker), swept at a thumb up or lost at a down. A landed pile within `RunState.pull_radius` (`PileRules.PULL_RADIUS` 96 plus the Reach line) is pulled to the player (`CoinPile.PULL_SPEED`, `PULL_ACCEL`); throws land in a ring past the reach (`RING_MIN` 112 to `RING_MAX` 160).
- Favour: `FavourRules.ACTS` is the table of acts (chain, dare, daring, clean_round, hit); a round's kills share `KILL_BUDGET` (40) over `RunState.round_enemies` (`kill_share`; a summon pays nothing but counts for the chain, the daring, and the grace), scored as `KILL_ACT` through `apply_kill`, the rest through `apply(value, act, gate_open)`. `Favour` (a Node under Main, one detector per act) emits `favour_changed(value, band, act)` on `RunState.elapsed`, and scores nothing while the run is not live. A dash passing within `DANGER_RADIUS` of a harmful enemy or `BOLT_RADIUS` (20) of an enemy bolt (`dash_past_bolt`) scores one `dare`; a kill within `DASH_WINDOW` of its end scores `daring` too. The decay (`decay`, `DECAY_ACT`): after `DECAY_GRACE` (2 s) without a scoring act (`is_scoring`) while the run is live (`run_started` to `player_fell`, `run_won`, `run_ended`, or `grounds_entered`) and unpaused, `DECAY_PER_SECOND` (4); a shot landing on the boss (a loud `enemy_hit`; never a status tick, `Health.last_hit_quiet`) restarts the grace with no points; a hit on any other enemy holds nothing off. The loss tally (`Favour.round_losses`, cleared at a round's start, live only): a hit's real drop under `hit`; a drain with a harmful enemy alive under `drain_source(distance, engaged)`: `slow` within `NEAR_RADIUS` (96) or engaged (a shot landed within `DECAY_GRACE`, `last_hit_time`, from a loud `enemy_hit` or `shot_blocked`), else `fled`; `round_loss()` is `main_loss` (the largest at `LOSS_FLOOR` 1 or more, ties hit, fled, slow; else `none`). The gate (`Favour.gate_open`, shut at `round_started` and `run_started`, opened by the round's first `daring`): while shut, `CAPPED_ACTS` stop at `ROAR_GATE` (74). Each `round_started` settles the meter down to `ROAR_GATE` (`settle`, `SETTLE_ACT`). Main emits `round_ended(band)` (the crowd's sound, `Audio.CROWD_SOUNDS`); the band sets the card count (`offer_count`: 3, `OFFER_COUNT_ROAR` 4); the heading is `UpgradeMenu.HEADING` ("Pick a boon"). On a Roar's first open the crowd's card (`crowd_slot`: last, or before the heal card when hurt) drops in after `CROWD_CARD_DELAY` over `CROWD_CARD_DROP` with `card_revealed()` (Audio: `crowd_roar`), in `UiTheme.FRAME_CROWD` tinted `CROWD_FRAME_TINT`; its pick waits for it. - Audio: every sound is a name in `data/audio.json` played by `Audio` on a bus signal; gameplay code never touches a player. A missing file is silence plus `AUDIO_MISSING` (`check_boot.sh` counts them). `Audio.reset()` runs in `SceneSuite.after_test`; `Audio.plays` counts plays by name; `min_gap` is measured on the Clock. `audio.gd` never names a gameplay Node class statically (it duck-types; `check_boot` catches a regression as leaked instances at exit); it may name a pure class (`GroundsRooms`). A sound that must outlive a pause that follows it (the crowd's `crowd_boo|quiet|cheer|roar`, `crowd_hush`, `player_die`, `verdict_roll` (cut by `Audio.stop_ui`), `verdict_up|down`, `gate`, the box's `bleep_<cast id>` on `dialogue_blip`, `buy_denied` on `pick_denied`) plays on the UI pool (`Audio.play_ui`); the coin sounds and the post's `buy`/`buy_denied` play on the game pool. The loops: `music_run`, `music_boss`, `music_grounds`.
- Profile: `Profile` (autoload after `Audio`) holds one `Save` (`scripts/save.gd`: money, training ranks, flags, `Save.STAT_KEYS`, the run log, the `story` section) loaded from `Profile.path` (`user://save.cfg`) and filled by the bus (one handler per signal). `Profile.commit()` is the only write to disk (the verdict, the purchases, every gate-screen pass, a story event's end (a box event at its close, an entry line at once; the verdict's and the pick's lines with the run's close), the title's wipe), never a listener. `dashes_through_danger` counts `dare`, `daring_kills` `daring`, `favour_peak` the meter's high. An unreadable file (corrupt, or a later `version`) is copied to `<path>.bak` before the defaults load. Every tool and test points `Profile.path` at its own scratch named with `OS.get_process_id()`, so nothing but the game writes the player's save. A new stat is a `STAT_KEYS` row (plus `PER_ID_KEYS` when nested by id); an older file loads it at its default. `player_hit` and `player_fell` carry `attacker_id` ("" unknown, filed under `Save.UNKNOWN_ID`).
- The fall and the verdict: `Player.hurt` at 0 hp calls `_fall` (`player_fell(position, attacker_id)`); after `VERDICT_HOLD` Main runs `_build_up` (`verdict_drum`, `camera.drift_to_top(box.centre(), VERDICT_DRIFT, VERDICT_ZOOM)`: `top_framed` at the base zoom times the factor, real-time tweens with the lean, the shake, and the smoothing suspended and the limits kept (the box `TOP_MARGIN` under the view's top, never the void), `drifting` until `end_drift` at the next run's start; the narrator's `verdict_wait` line in the timed window; `VERDICT_PAUSE`), then `_verdict(false)`; `_win` emits `run_won` and after `WIN_HOLD` calls `_verdict(true)`. On a fall `VerdictRules.decide(band, hits_taken, flags, cheats)` (pure; UP unless `thumbs_down` until M9), the `ThumbSign` over the box with the narrator's `verdict_up`/`verdict_down` line, and `verdict_given(up)`; a win has no thumb, no narrator, and no `verdict_given`. Then the piles swept on an UP, `_bank` (money and `coins_earned` on UP, `coins_lost`, `deaths`, `deaths_by` on DOWN, `runs`, `wins`/`falls`, `perfect_runs`, `best_run`, `boss_time_best`, `log_run`, `Profile.commit()`, `run_ended("win"|"fall")`), `RUN_END ...`, `VERDICT_SHOW` 2.5 (a win `WIN_SHOW` 1.2), the window hidden, `FADE_TIME`, and `show_gate(up, record, save)` (the title `VerdictRules.gate_name`). `restart()` mid-run (R, Restart, Quit to title) is a yield (`run_ended("yield")`, the coins to `coins_lost`, a run and a fall counted, the record logged with an empty verdict, committed; guarded on `_ended` and the title). `restart()` and `quit_to_title()` return while `_verdict_pending()`, so a run is recorded once. The verdict scene's times are real time by design.
- Headless generator scripts (`tools/gen_*.gd`, `tools/icon_sheet.gd`) run with `-s` and must `quit()` on every path; a failed `assert` hangs the process, so they report with `push_error` and `quit(1)`. Run them under `perl -e 'alarm 120; exec @ARGV'`.
- Arena geometry: a run is a `SeriesDef` (`data/series/tier_1.tres`: the arena size and eight `RoundDef`s) fought in one `Room` that lives for the run; `_enter_round` hands the runner the next table after the pick and `ROUND_GAP`. The arena is 28x15 tiles of 16 px (one screen at 3x zoom): a two-row top wall with the emperor's box (`EmperorBox`) at x 208..240, one-row side and bottom walls, a 26x12 floor (`ArenaGrid.bounds`). A grounds room is the same grid at its def's size, with the doors' gaps (`ArenaGrid.door_gap`). All of it derives from `ArenaGrid`; never hardcode an arena coordinate. CanvasLayers: HUD 1, Prompt 2, the menus, the panels, and the DialogueBox 10, Title 15, Fade 20, GateScreen 30.
- Feel constants live next to what they affect: `juice.gd` (trauma decays on the Clock: a hitstop does not slow it), the tops of `enemy.gd`, `player.gd`, `boss.gd`, `dash_rules.gd`, `status_effects.gd`, `projectile.gd`, `camera.gd`, `thumb_sign.gd`, `coin_pile.gd`, `ui/coin_flight.gd`, `ui/hud.gd`, the UI panels (`ui/upgrade_menu.gd`, `ui/build_screen.gd`, `ui/training_panel.gd`, `ui/armoury_panel.gd`, `ui/dialogue_box.gd`, `ui/key_cap.gd`), `grounds.gd`, `cast_figure.gd`, `story_mark.gd`, `door.gd`; the verdict's holds, the fade, `ROUND_GAP`, `PICKER_DELAY`, `PILE_WAIT_CAP`, `ENTRY_LINE_TIME` in `main.gd`; the lock in `upgrade_catalog.gd`; the story's caps in `story/story_catalog.gd`; the rules tables in `favour_rules.gd`, `pile_rules.gd`, `training_rules.gd`, `verdict_rules.gd`; data in `data/*.tres` and `data/grounds/`.

## Tests

- gdUnit4 with `report/godot/push_error=true`: a `push_error` during a test fails it. Autoloads are live in the runner.
- Scene tests wait on `get_tree().physics_frame` or on the Clock, never the OS clock, so a run is the same at fixed fps and in real time. `SceneSuite.real_seconds(t)` is a timer on the engine's unscaled step, used only for what is real time by design (hitstop, `Main.ROUND_GAP`, the verdict scene's `WIN_HOLD`, `WIN_SHOW`, `VERDICT_*`, `FADE_TIME`, `PICKER_DELAY`, `ENTRY_LINE_TIME`, `Audio.MUSIC_FADE`, the boss's `CORPSE_FLASH_HOLD`, `Fx.BOSS_DEATH_STAGE`); a test waiting for the next round uses `wait_for_round(main, index)`. `wall_msec(ms)` is the one wait on the OS clock (blocking), for the mixer's thread only.
- Every scene test extends `SceneSuite` (`tests/support/scene_suite.gd`) and builds Main with `quiet_main()` or `quiet_main_with_series()` (the title off, `Room/WaveRunner` disabled). `before_test` resets `Juice` (the last test's scene can still start a hitstop after its `after_test`), points `Profile.path` at `PROFILE_SCRATCH`, and puts `Story` on the empty fixture; `after_test` awaits a frame (so a node freed in the last line is no orphan), then resets `Juice`, `RunState`, `Audio`, and the profile and removes `PROFILE_SCRATCH` and `SETTINGS_SCRATCH` (per-process `static var`s); an override calls `await super()`. A pure suite uses its own scratch path and never touches `Profile`. Never add a second `RunState` to the tree. Helpers: `stand_at(main, id)` (an area pairs two or three ticks after a placement: wait with `wait_until`, never a bare tick count), `interact()`, `press_action(action)` (an `InputEventAction` through `Input.parse_input_event`; `Input.action_press` never reaches an `_unhandled_input`), `through_box`, `go_through`, `take_the_lift`, `pass_the_gate` (the gate screen), `fall_to_the_gate`, `clear_and_pick` (never a Switch or the locked card), `plays(name)`, `click_control`, `hover_control`/`hover_at` (end a hovering test with `hover_at(Vector2.ZERO)`; a mouse event goes through `get_viewport().get_final_transform()`, the headless window being 64x64).
- Tests never depend on the shipped prose: `before_test` puts `Story` on `tests/support/story_empty/`; a story suite calls `use_story("res://tests/support/story")` (or `tests/support/story_arrival/` for `arrival`). Only `tests/test_story_data.gd` reads `data/story/`, asserting validity, never a sentence; a test of the crowd's or the narrator's pool checks the picked event's shape, never its id. A test never depends on a gitignored asset: it overrides the stream with a generated one (as `test_audio.gd` does).
- Follow TDD: write the failing test, run it, implement, run again. During TDD run the touched suites (`-a`); run the full suite once before committing. A second run only for a change that draws from `RunState.rng` or a seeded stream in a test that does not seed it (`after_test` reseeds from `randi()`). A change that touches the clock itself (`Clock`, a real-time wait's helper, what reads the Clock) also runs `tools/test.sh --realtime` once by hand.

## Process

- A new plan names the files, the behaviour, and the tests, with short snippets where the shape matters; it does not paste whole files.
- One agent in the checkout at a time: implementers, reviewers, and the coordinator share one working tree, so a coordinator commit made while an implementer works uses explicit paths (`git commit -- <files>`), never `git add -A` (it sweeps the implementer's edits into the wrong commit). Reviews are read-only. Two test runners on one machine are safe: the scratch profile, the settings scratch, and the test log are per process.
- The build loop per task: an implementer, a spec-compliance review, a code-quality review, one fix pass, a re-review. A small tuning task may take one combined review. An agent cut off by a usage limit is resumed with `SendMessage` (check `git status` first).
- Milestones close only on the user's playtest verdict. Keep the plan document in sync with every deviation from it.
- Show, don't tell (the colosseum design): no caption, hint, tutorial, label, or character line explains a mechanic or addresses the player. UI may name, never narrate: a thing may carry its name (the post's rows, the pause screen's tabs, "Pick a boon") and a hovered line may say what it buys, but nothing says how a system works; a meter has no name, the gate screen names the gate. Text may reinforce, never explain: a line in the world's voice that reinforces a feeling the player already has is in (the crowd's judgement at the pick, the narrator at the verdict); a line that breaks the fourth wall, infodumps, or says how a system works is out. Every spec-compliance review checks this as a spec item, and `docs/TESTERS.md` may name a mechanic in a question but never explain one.
- Do not downgrade silently when a step needs the user (downloads, logins): put it in the plan as a user action and work around it.
