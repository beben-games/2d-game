## Commands

- `tools/test.sh` runs every gdUnit4 suite headless; exit 0 pass, 100 failures, 105 script errors, 1 if no tests found. `tools/test.sh -a res://tests/<file>.gd` runs one suite. The engine runs at `--fixed-fps 60` by default (a 1/60 s step a loop iteration, never waiting on the wall clock); `--realtime` paces it on the wall clock as the game is; `-v` streams the full output; both flags come before `-a` (a flag after `-a` is refused, before the import step). It prints a digest (each failed test with its report, script errors, the summary line) from its own `reports/test_<pid>.log`, which is moved to `reports/test.log` at exit (with two runners, the last to finish owns `test.log`). Read the log only when the digest is not enough.
- `tools/check_boot.sh` boots the main scene headless and fails on any `ERROR:`/`WARNING:` line, then runs the reload probe (`tools/reload_probe.gd`, under `--fixed-fps 60`: Play, Restart, a fall to the gate screen, the grounds, Quit to title, Play into the Ludus, its top door, the lift, Quit to title from the run; `RELOAD_PROBE ok`). Godot exits 0 even when the main scene fails to load, so never use its exit code alone.
- `tools/smoke.sh [idle|move|combat|kill|round|fall|wake|pick|roar|boo|title|pause|boss|grounds|rooms|talk]` opens a window for a few seconds, drives input in physics ticks, and writes `reports/smoke_<scenario>.png` plus `SMOKE_` lines; every scenario but `idle`, `move`, and `combat` asserts its key lines. `round`, `fall`, `wake`, `pick`, `roar`, and `boo` run on `tools/smoke_series.tres` (two rounds of one chaser). `round` takes card 1 and waits the gap (`SMOKE_ROUND 1`); `fall` kills the player beside a chaser, saves `reports/smoke_fall_verdict.png` at the thumb once the narrator's line is whole (`SMOKE_VERDICT up`, `SMOKE_NARRATOR verdict_up`) and ends on the gate screen (`SMOKE_GATE Porta Triumphalis`; the end capture is the screen over the black, dark by design); `wake` falls under `verso` (`SMOKE_GATE Porta Libitinaria`), passes the gate screen into the Spoliarium (`SMOKE_WAKE spoliarium prone=true`; `SMOKE_WAKE_LINE <ids> timed= top=` unasserted), saves `reports/smoke_wake_prone.png` with the narrator's line whole, and rises on a move press (`SMOKE_ROSE true`); `pick` also saves `reports/smoke_pick_menu.png` with the cards up and asserts the crowd's line (`SMOKE_CROWD_LINE crowd.<name>`); `roar` runs the `pick` flow at `FavourRules.MAX` favour, saves `reports/smoke_roar_menu.png` after the crowd's card lands, and asserts `SMOKE_ROAR 4` and `SMOKE_CROWD_ROARS 2` (the round's end and the drop); `boo` runs it at a Boo (the meter at 0, a hit tallied, the kill budget spent), saves `reports/smoke_boo_menu.png`, and asserts the crowd's line and `SMOKE_BOO_LOCKED <index>`; `title` saves the paused front door as `reports/smoke_title_screen.png` before Play and `pause` the pause screen as `reports/smoke_pause_menu.png` (the unconditional end capture `smoke_<scenario>.png` is the run after); `boss` runs on `tools/smoke_boss_series.tres`, shoots the boss until its first ring, and asserts `SMOKE_BOSS_HP n of 600` below max under a visible bar. The grounds' three set `flags.returned` on the scratch profile and Play into the Ludus: `grounds` saves `reports/smoke_arrival.png` with the first arrival's line whole (`SMOKE_ARRIVAL <pool>.<name> open=true`), walks up to the post (`reports/smoke_grounds_key.png`: the key cap over it, the lanista's mark), presses E through the lanista's word (`SMOKE_GROUNDS_WORD lanista.<name>`), and asserts `SMOKE_GROUNDS post` (the end capture has the training panel up); `rooms` (with `spoliarium_seen`) walks every door by real input, `reports/smoke_room_<id>.png` for each room and `reports/smoke_room_door_key.png` (the cap over the Ludus's left door), asserting `SMOKE_ROOMS ludus armamentarium sanitarium hypogeum spoliarium`; `talk` walks to the veteran (`smoke_talk_mark.png`, `smoke_talk_key.png`), presses E, saves `smoke_talk_box.png` (the first line whole) and `smoke_talk_choices.png`, takes the first choice, and asserts `SMOKE_TALK veteran.<name> open=false`. The story's checks match a pool and a shape, never an event's name (the names are the writer's). Every scenario fails if it ran silent (`SMOKE_AUDIO 0`). A 30 s in-process watchdog; smoke.sh reports `watchdog: scenario hung`. Read the PNG to verify visuals. The smoke tool and the reload probe point `Profile.path` at their own per-process scratch (`user://smoke_profile_<pid>.cfg`, `user://probe_profile_<pid>.cfg`, removed at the end) so no tool ever writes the player's save.
- `tools/release.sh [version]` publishes the built zips as the GitHub release `v<version>` of https://github.com/beben-games/2d-game (a `-rc` version is a pre-release; needs `gh auth login` and the commit pushed).
- `tools/run.sh [--seed=N]` plays the game from the project with the Godot binary; the user's way to run locally.
- `tools/build.sh [version]` exports the tester zips (Windows x64 and Linux x64, release, `export_presets.cfg`, `docs/TESTERS.md` as the README) into `builds/` (gitignored). Needs the 4.7.2 export templates installed in the editor. The version comes from `config/version` in `project.godot`.
- `tools/gen_atlas.py` regenerates `data/atlas.json` from the tileset's tile list. Sprites are always looked up by name through `SpriteAtlas`; never hardcode atlas pixel coordinates.
- `tools/gen_icons.py` regenerates `data/icons.json` (card and HUD icons by name, from a (row, col) table on the Raven sheet). Headless Godot generators, run as `source tools/godot.sh && perl -e 'alarm 120; exec @ARGV' "$GODOT_BIN" --headless --path . -s tools/<script>.gd </dev/null`: `gen_guns.gd` (the handgun sprite from the user's pistol sheet), `icon_sheet.gd` (renders every icon to `reports/icons.png` for a check by eye).
- Art tools (Python, `tools/art/`): `budget.py` reads the PixelLab balance and prints what an art session may spend (`--left N` offline); `pixellab.py balance` is the REST client's check. The API key is read from the macOS login keychain (`tools/art/keys.py`, service `pixellab-api-key`) and never printed, logged, or written; `git config core.hooksPath tools/hooks` enables the pre-commit hook that refuses a staged key or `.env`.
- Godot binary: `source tools/godot.sh` exports `GODOT_BIN` (/Applications/Godot.app/Contents/MacOS/Godot, 4.7.2).

## Conventions

- Commits: no global git identity on this machine. Use `git -c user.name="Benjamin Zigh" -c user.email="78459259+beben-games@users.noreply.github.com" commit` and end messages with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- The repo is public at https://github.com/beben-games/2d-game (`origin`), code MIT (`LICENSE`), assets per `CREDITS.md`. Packs whose terms forbid reposting (Raven icons, the pistol sheet, the Minifantasy and Classic Monster sounds, both music loops, the reserve sets) are gitignored and never committed: they live in the working copy and ship only inside the builds (`docs/ASSETS.md`). A new asset gets a `CREDITS.md` row with its license and an "In the repo" verdict before it is committed. Without them `IconAtlas` draws a placeholder (`ICON_MISSING`) and `Audio` plays silence.
- Commit Godot's generated `.uid` and `.import` files. `reports/` and `.godot/` are ignored. Never edit `addons/gdUnit4` (vendored upstream v6.2.1).
- The login shell is zsh; tool scripts are bash and are executed, never sourced.
- Physics layers: 1 player, 2 enemies, 3 player_shots, 4 enemy_shots, 5 walls (bit values 1, 2, 4, 8, 16), 6 pickups (bit 32): the coin pile (`scenes/coin_pile.tscn`, an `Area2D` masking 65 with monitoring off until its toss lands), 7 player_dashing (bit 64): the player's body layer during a dash; enemies never mask it (a trigger that must see a dashing player masks 65, as the pile and every `Interactable` do). Player body mask is 18 (walls, enemies), or 16 (walls only) while dashing; enemy bodies 19 (walls, enemies, player). Player shots mask 2 (enemies only) and enemy bolts mask 0; walls are handled by the projectile's raycast against layer 5 (`Projectile.WALL_MASK`). Enemy bodies are solid; damage reaches the player only through the hurtbox. An enemy's bolt carries the group `Projectile.ENEMY_BOLT_GROUP` (`enemy_bolts`) from `scenes/enemies/enemy_bolt.tscn` itself (both firers instantiate it; the player's `projectile.tscn` never does), its motion `Projectile.velocity()`. In the grounds a door's blocker and a cast member's lower body are `StaticBody2D`s on the walls' layer (`Projectile.WALL_MASK`). A shielded enemy (`EnemyDef.shield`) blocks a player shot arriving inside its front arc through `Enemy.blocks_shot(direction, pierce)`, which `Projectile._on_body_entered` asks duck-typed before `take_damage`, unless the shot's pierce is at least `Enemy.SHIELD_PIERCE` (3); the rules are `ShieldRules`, the facing follows the enemy's movement at `shield_turn_degrees` a second and holds under a stun. The boss (`scenes/enemies/boss.tscn`) is an enemy body too (layer 2, mask 19) in the group `boss`; only a `StaticBody2D` (a wall) ends its charge; its summons carry the group `summoned`, which `WaveRunner` ignores.
- Time: game code under `scripts/` times by `Clock.now_usec()` (the engine's unscaled step: one `ignore_time_scale`, `process_always` scene-tree timer rotated at half its day-long `SPAN`, the clock every `create_timer(t, true, false, true)` runs on; wall time in the game, 1/60 s a frame under `--fixed-fps`), never `Time.get_ticks_*`: Juice's trauma decay and hitstop end, Audio's `min_gap`, and the text box's reveal read it; the one exception is Audio's release loop at quit, which waits on the mixer's thread. Tools (the smoke tool, the probes) keep real time. `Clock` is the first autoload and reads 0 before its `_ready`, so no autoload reads it in an initializer.
- Randomness: shot spread and the shooter's recover jitter (`Enemy.RECOVER_JITTER`) use `RunState.rng`; systems whose placement must depend only on seed and time use `RunState.stream(name)`; cosmetic effects use the global RNG; the arena floor derives its own RNG from the seed.
- Cheats: `scripts/cheats.gd` holds the code words typed into the title's seed field, in two tables: `CODES` (a word to the run's flags) and `ACTIONS` (a word to a title-time action, never a run flag: `tabula` is `"wipe"`); a word is in one table or the other, and a code word is never a seed. `Cheats.parse(text)` is pure and gives `{"seed", "cheats", "action"}` (an action word: a random seed, no flags); the title emits `play_pressed(seed, cheats, action)` and `Main.play(seed, cheats, action)` runs a `"wipe"` through `Profile.wipe()` before it reads `flags.returned`, so the run that follows is an uncheated first run (the arena, the grounds after the gate). `Profile.wipe()` copies the file at `path` to `<path>.bak` (`Save.back_up(path)`, which returns the copy's `Error`), replaces the live Save with `Save.new()`, and commits; a failed copy wipes nothing (a warning, the Save as it was, `false`). `RunState.cheats` holds the run's flags, set by `start_run(seed, cheats)` and empty otherwise; the readers are `Player.hurt` (`immortal`, `permawhat?`), `RunState.start_run` (`rich`, `dives`: the run starts with `RICH_COINS`), and `VerdictRules.decide` (`thumbs_down`, `verso`: the thumb turns down); the gate screen's run block, the run's record, and the `RUN_END` print say `cheats=<flags>` (`Cheats.describe`) so a cheated run is never mistaken for a real one.
- Coins: `EnemyDef.coins` is the enemy's worth; `RunState.add_coins(value)` is the one writer of the run's coins and the one emitter of `coins_changed` (Main's `_pay` for a kill and the Cheer bonus, a `CoinPile` on contact, the sweep at a thumb up). A kill's coins fly to the HUD counter as a cosmetic `CoinFlight`; a Roar's tally and the boss's coins are thrown as `CoinPile`s (`Main.throw_piles`, deferred: a pile is a physics body) at `PileRules.spots` drawn from the round's `piles:<round>` stream; piles live under `Room/Piles`, survive the picker, and are swept into the counter at a thumb up or lost at a thumb down. A landed pile within `RunState.pull_radius` (`PileRules.PULL_RADIUS` 96 at `start_run`; a training line widens it later) is pulled to the player each physics tick (`CoinPile.PULL_SPEED`, `PULL_ACCEL`; the player found once at `land()` through the `player` group); every throw lands in a ring past the reach (`PileRules.RING_MIN` 112 to `RING_MAX` 160, clamped inside the floor, on the open side near a wall), so the piles wait to be walked to.
- Favour: `FavourRules.ACTS` is the one table of acts and their values (chain, dare, daring, clean_round, hit), all but the kill's: a round's kills share `KILL_BUDGET` (40) over `RunState.round_enemies` (set by `Main._enter_round` from the round's `total_enemies()` before `round_started`), each paying `FavourRules.kill_share(enemies, paid, summoned)` (`kill_value`; the clamp to what `Favour.round_kill_paid` left of the budget only guards kills beyond the table's count, none in the shipped series); a summon (group `summoned`, not in the table) pays and spends nothing but is still a kill for the chain, the daring, and the decay's grace; the kill is scored as `KILL_ACT` through `FavourRules.apply_kill(value, share, gate_open)`, the table's acts through `apply(value, act, gate_open)` (one gated helper under both); `Favour` (a `Node` under Main) holds one detector per act on the bus, emitting `favour_changed(value, band, act)`; its clock is `RunState.elapsed` (never wall time), and nothing scores while the run is not live (a kill after the fall or the win, the boss's summons dying after it). A dash whose path passes within `DANGER_RADIUS` of a harmful enemy, or within `BOLT_RADIUS` (20) of an enemy bolt in flight (`FavourRules.dash_past_bolt`: the closest approach over `DashRules.DURATION`, each bolt advanced along its velocity, estimated at the dash's start), scores one `dare` at once (`Favour._on_player_dashed`), and a kill within `DASH_WINDOW` of that dash's end scores `daring` on top. The decay (`FavourRules.decay`, `DECAY_ACT`): after `DECAY_GRACE` (2 s) since the last scoring act (one that raises the meter, `FavourRules.is_scoring`: a hit on an enemy that does not kill holds it off no longer) while a run is live (`Favour._run_live`: from `run_started` to `player_fell`, `run_won`, `run_ended`, or `grounds_entered`) and the tree unpaused, the meter loses `DECAY_PER_SECOND` (4 a second); running away, idling, and the gap between rounds all decay, killing keeps the meter. A shot landing on the boss (a loud `enemy_hit` on the group `boss` while the run is live; a status tick, `Health.last_hit_quiet`, is not one) restarts the grace with no points and no `favour_changed`; a hit on any other enemy, a summon included, holds nothing off. The round's loss tally (`Favour.round_losses`, cleared at a round's and a run's start, filled only while the run is live): a hit adds what the meter really lost under `hit`; a draining tick with a harmful enemy alive adds its drain under `FavourRules.drain_source(distance, engaged)`: `slow` within `NEAR_RADIUS` (96) of the nearest or while engaged (a shot landed within `DECAY_GRACE`: `Favour.last_hit_time`, from a loud `enemy_hit` on any enemy or a `shot_blocked`), `fled` far and not engaged, nothing with no enemy; `round_loss()` is `FavourRules.main_loss` (the largest tally at `LOSS_FLOOR` (1) or more, ties broken hit, fled, slow; `none` else). The round's gate (`Favour.gate_open`, closed at `round_started` and `run_started`, opened by the round's first `daring`): while closed, kills, chains, dares, and the clean round never lift the meter past `ROAR_GATE` (74, one under the Roar edge; `CAPPED_ACTS`); once open they add in full up to `MAX`, so no round reaches Roar without a daring kill. The crowd settles at each `round_started` (`FavourRules.settle`: the meter clamped down to `ROAR_GATE`, emitted as `SETTLE_ACT` "settle" only when it changes), so every round's Roar takes its own daring kill. Main emits `round_ended(band)` at every round's end (the crowd's sound, `Audio.CROWD_SOUNDS`), and the band sets the card count only (`FavourRules.offer_count`; `OFFER_COUNT` 3, `OFFER_COUNT_ROAR` 4); the heading over the cards is `UpgradeMenu.HEADING` ("Pick a boon") on every band. On a Roar's first open the crowd's card (`UpgradeMenu.crowd_slot`: the last slot, or the one before the heal card when hurt) is held by an empty Control, then built after `CROWD_CARD_DELAY` and dropped from above the view's top over `CROWD_CARD_DROP` with `card_revealed()` (Audio: `crowd_roar`), in `UiTheme.FRAME_CROWD` tinted `CROWD_FRAME_TINT` with the crowd's heads on its top bar; the pick of that slot waits for it. An Offer rank's cards, a refund round, and a reroll land at once. The meter has no label (an icon beside it names it, never a word): the crowd's sound is its explanation.

## Tests

- gdUnit4 with `report/godot/push_error=true`: a `push_error` during a test fails it. Autoloads are live in the runner.
- Scene tests wait on `get_tree().physics_frame` or on the Clock, never the OS clock, so a run is the same at `--fixed-fps` and in real time. `SceneSuite.real_seconds(t)` is a timer on the engine's unscaled step (wall time in the game and under `--realtime`, 1/60 s a frame under `--fixed-fps`; neither a pause nor a hitstop slows it), used only for what is real time by design: hitstop, the round gap (`Main.ROUND_GAP`), the verdict scene (`Main.WIN_HOLD`, `WIN_SHOW`, `VERDICT_HOLD`, `VERDICT_DRIFT`, `VERDICT_PAUSE`, `VERDICT_SHOW`, `FADE_TIME`), the picker delay (`Main.PICKER_DELAY`), the entry line (`Main.ENTRY_LINE_TIME`), the music crossfade (`Audio.MUSIC_FADE`), the boss's `CORPSE_FLASH_HOLD`, and `Fx.BOSS_DEATH_STAGE`; a test waiting out the gap for the next round uses `wait_for_round(main, index)`. `wall_msec(ms)` is the one wait on the OS clock (blocking, then a frame), for the mixer's thread only (the pool-steal case).
- Every scene test extends `SceneSuite` (`tests/support/scene_suite.gd`) and builds Main with `quiet_main()` or `quiet_main_with_series()`, which set `start_at_title` false and disable `Room/WaveRunner` so nothing spawns on its own (the one `Room` lives for the run, so the runner stays off unless a test turns it on). `before_test` resets `Juice` (gdUnit awaits frames after `after_test`, so the last test's scene can still land a hit and start a hitstop that would freeze this test's first frames), points `Profile.path` at `PROFILE_SCRATCH` and resets it, and puts `Story` on the empty fixture; the base `after_test` resets `Juice`, `RunState`, `Audio`, and the profile, and removes the scratch files (`PROFILE_SCRATCH` and `SETTINGS_SCRATCH`, both `static var`s named with the process id); a suite that overrides either calls `super()`. Never add a second `RunState` to the tree. In the grounds: `main.enter_grounds()` on a quiet Main, `stand_at(main, id)` (the player on an interactable's stand position until it is the focus: an area pairs two or three ticks after a placement, so wait with `wait_until`, never a bare `ticks(2)`), `interact()` and `press_action(action)` (an `InputEventAction` through `Input.parse_input_event`, delivered at the next frame's flush; a bare `Input.action_press` never reaches an `_unhandled_input`), `through_box(main, choice)`, `go_through(main, to)`, `take_the_lift(main)`, and `pass_the_gate(main)` (the gate screen passed with Enter, until the grounds are up and the black has lifted); also `plays(name)`, `fall_to_the_gate(main)`, `wait_for_round`, `clear_and_pick(main)` (never a Switch, never the locked card), `click_control(control)`, and `hover_control(control)`/`hover_at(window_position)` (a mouse motion; a test that hovers ends with `hover_at(Vector2.ZERO)` so the next starts unhovered) (a mouse event for a Control goes through `get_viewport().get_final_transform()`: the headless runner's window is 64x64, scaled). The base `after_test` awaits a frame first so a node freed in a test's last line is not counted as an orphan: an override must `await super()`.
- Tests never depend on the shipped prose: `SceneSuite.before_test` puts `Story` on `tests/support/story_empty/` (a cast and nothing else) so no event fires in a suite that did not ask for one; a story suite calls `use_story("res://tests/support/story")` (characters, a narrator, and events covering every construct) or `tests/support/story_arrival/` (the `arrival` cases), and `after_test` puts the empty one back. Only `tests/test_story_data.gd` reads `data/story/`, and it asserts validity (no load error, the seven cast ids, each speaker's sprite and bleep, every room's people in the cast, no line naming a key), never a sentence or an event's name; a test that reads the crowd's or the narrator's pool checks the picked event's shape (its trigger, its condition's names), never its id. A test never depends on a gitignored asset (a clone has none of them): it overrides the stream with a generated one (`test_audio.gd`, the wake suite's `music_grounds`).
- Follow TDD: write the failing test, run it, implement, run again. During TDD run the touched suites (`-a`); run the full suite once before committing. Run it a second time only for a change that draws from `RunState.rng` or a seeded stream in a test that does not seed it (`after_test`'s `RunState.start_run()` seeds from `randi()`, so such a test can pass once on a lucky seed; the run costs seconds). A change that touches the clock itself (`Clock`, a real-time wait's helper, what reads the Clock) also runs `tools/test.sh --realtime` once by hand.

## Process

- A new plan names the files, the behaviour, and the tests, with short snippets where the shape matters; it does not paste whole files (git holds the code, and long plans cost every reader).
- One agent in the checkout at a time: implementers, reviewers, and the coordinator share one working tree, so a coordinator commit made while an implementer works uses explicit paths (`git commit -- <files>`), never `git add -A` (it sweeps the implementer's uncommitted edits into the wrong commit; it happened once and had to be rebuilt). Reviews are read-only. Two test runners on one machine are safe: the scratch profile, the settings scratch, and the test log are per process (`reports/test_<pid>.log`, moved to `reports/test.log` at exit, so the last runner to finish owns it).
- The build loop per task: an implementer, a spec-compliance review, a code-quality review, one fix pass, a re-review. A small tuning task (one file of numbers and its tests) may take one combined spec-and-quality review instead of two. An implementer or reviewer cut off by a usage limit is resumed with `SendMessage` (its context survives; check `git status` first: a clean tree means nothing was lost).
- Milestones close only on the user's playtest verdict. Keep the plan document in sync with every deviation from it.
- Show, don't tell (the colosseum design): no caption, hint, tutorial, label, or character line explains a mechanic or addresses the player; UI may name, never narrate (refined on M5's playtest 1: a thing may carry its name, as the post's rows, the pause screen's tabs, and the picker's "Pick a boon" do, and a hovered line may say what it buys, but nothing says how a system works); a panel shows its objects, a meter has no name, the gate screen names the gate. Text may reinforce, never explain (refined on M5's playtest 3, 2026-10-01: it is a writing rule as much as a design rule; a line in the world's voice that reinforces a feeling the player already has is in, such as the crowd's one-sentence judgement at the pick or the narrator's window at the verdict, both M6's; a line that breaks the fourth wall, infodumps, or says how a system works is out). Every spec-compliance review checks this as a spec item, and the tester file (`docs/TESTERS.md`) may name a mechanic in a question but never explain one.
- Do not downgrade silently when a step needs the user (downloads, logins): put it in the plan as a user action and work around it.
