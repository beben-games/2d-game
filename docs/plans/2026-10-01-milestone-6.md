# Milestone 6 Implementation Plan: the colosseum grounds

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** The grounds become five rooms with people in them, and the game gains a Hades-like story system (pools of events per character, gated on each other and on what the player has done) shown in a text box, at the verdict, and at the pick; then a Story tab of our own in the Godot editor to maintain the events.

**Architecture:** Pure classes under `scripts/story/` parse plain-text pools (`data/story/<character>.txt`), validate them as `UpgradeCatalog` validates cards, and pick the next event for a pool, a trigger, and a context; a `Story` autoload after `Profile` holds the catalog and keeps the story's state in a new section of the `Save`. `Grounds` becomes one room built from a `GroundsRoomDef`, mounted through Main's existing stage slot once per room, with every station, door, and character an `Interactable` on one key. A `DialogueBox` presents events (paused, with input) and timed lines (the narrator at the verdict); the picker shows the crowd's line. Phase 2 adds an editor plugin (`addons/story_graph/`) over the same pure classes.

**Tech Stack:** Godot 4.7.2, GDScript, gdUnit4 (`tools/test.sh`), the smoke tool (`tools/smoke.sh`), Godot's `GraphEdit` for the Story tab.

**Design:** `docs/plans/2026-10-01-milestone-6-design.md` (the intent, the file format, the user's answers) under `docs/plans/2026-09-25-colosseum-design.md` (the direction). This plan is in the short form: files, behaviour, tests; the committed code is the reference once a task lands.

**Phases:** Tasks 1 to 10 are phase 1 (the game side, closing on the user's playtest of `0.6.0-rc1`); Tasks 11 to 17 are phase 2 (the writer's kit, closing on the user writing events with the tab). `m6` is tagged after both.

## The file format (the reference for Tasks 2, 11, and 15)

```text
# a comment; a comment block directly above "==" belongs to that event
== the_warning                      # the event's name; its id is "<pool>.<name>" (veteran.the_warning)
requires: lanista.after_first_win, doctor.the_wound
unless: veteran.the_goodbye
when: deaths >= 1 and not veteran_distant
priority: high                      # story | high | normal | filler; default normal
repeat                              # or "once", the default
trigger: talk                       # talk (default) | enter <room> | verdict_wait | verdict_up | verdict_down | pick
act: 2                              # optional, 1..3

VETERAN: PLACEHOLDER {wins} nights, and you still walk.
[last_verdict == down] VETERAN: PLACEHOLDER I saw them carry you out.
? PLACEHOLDER Say nothing.
    set: veteran_distant
? PLACEHOLDER "So did you."
    set: veteran_trust
    VETERAN: PLACEHOLDER Hm.
set: veteran_met                    # an unindented effect after the body runs at the event's end
```

- Header keys come before the first blank line; the body follows. A speaker is a cast id in capitals. `set: flag` sets a bool flag true; `set: flag = 3` or `= word` sets a value of the flag's declared type.
- Conditions: `or` under `and` under `not` under a comparison (`==`, `!=`, `<`, `<=`, `>`, `>=`) of a name with a literal (an integer, `true`, `false`, or a bare word) or another name; parentheses; a bare name is its truth.
- Names a condition or a `{substitution}` may read: every declared story flag; the profile's flags (`runs`, `wins`, `falls`, `deaths`, `perfect_runs`, `returned`, `spoliarium_seen`); the last run's facts `last_outcome` (`win`, `fall`, `yield`, `none`), `last_verdict` (`up`, `down`, `none`), `last_band` (`boo`, `quiet`, `cheer`, `roar`, `none`), `last_killer` (an enemy id or `none`); at the pick `round_band` and `round_loss` (`hit`, `fled`, `slow`, `none`); at the verdict `run_band`. A word-valued name compared with a word outside its list is a load error.
- `data/story/flags.txt`: one flag a line, `name` (a bool, false) or `name = 0` (an int) or `name = word`.
- `data/story/cast.json` is the pools' index (no directory listing: an exported build reads by name): `{"lanista": {"name": "PLACEHOLDER Lanista", "sprite": "ogre_idle_anim", "bleep": "bleep_lanista"}, ..., "narrator": {..., "timed": true, "silhouette": true}, "crowd": {"timed": true}}`. A pool is `data/story/<id>.txt` for every cast id; a missing file is an empty pool. `timed` is `true` or `false`; `name` is a string, needed by every member that is not timed. Every event of a timed member's pool is timed, whatever its trigger.
- Comments (pinned in Task 2's review; Task 11 writes them back): a line starting with `#` (after any indentation) is a comment anywhere, kept as its text without the `#` and one blank after it. The first block at the top of the file followed by a blank line is the file's header; a block before an event (directly above its `==` or across blank lines) is the event's comment; a comment among the header keys is one of the event's header notes; a comment in the body is kept in place (in the choice's lines when indented under one) and never played; a block after the last line is the file's footer. An inline comment (a `#` after a blank) is allowed only on the `==` line, a header line, and an effect line, where it is stripped with a warning (a rewrite drops it); in a speaker line's or a choice's text a `#` is prose.
- An integer is digits with an optional leading `-` and no leading zero (`0`, `3`, `-2`; never `+3`, `03`, `-0`), in conditions, effects, flags, and `act`. A trigger's word and its room are split on any blanks. A choice or a speaker line with no text, and an id twice in one `requires:` or `unless:` list, are errors. An event whose `requires` or `unless` names an event that did not load does not load either (one error naming the cause).
