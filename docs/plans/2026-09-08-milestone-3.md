**Goal:** The room-clear moment becomes a paused three-card upgrade menu drawing from per-weapon pools, with a second weapon (the crossbow), a weapon switch that re-picks, status effects on enemies, dash charges, heart containers, a build strip on the HUD, a Tab build screen, and an eight-room floor.

**Architecture:** The run holds a `Build` (weapon id plus upgrade ranks). A pure fold turns it into the `WeaponDef` the player fires with; nothing mutates weapon data. `UpgradeDef` files list modifiers per rank; `UpgradeCatalog` loads them and computes the pool. `UpgradeMenu` is a CanvasLayer that pauses the tree and keeps processing. Projectiles move by raycast so they can bounce and never tunnel. A `StatusEffects` child on every enemy holds burn, stun, and chill.

**Tech Stack:** Godot 4.7.2, GDScript, gdUnit4 (vendored, `tools/test.sh`), Python 3 for the icon index generator, Godot headless scripts for the asset generators.

**Design:** `docs/plans/2026-09-08-milestone-3-design.md`. Pre-work: `docs/plans/2026-09-08-m3-prework-notes.md`.

## Read this first

- Every command below runs from the repo root. `tools/test.sh` runs all suites; `tools/test.sh -a res://tests/<file>.gd` runs one. `tools/check_boot.sh` boots the main scene headless. `tools/smoke.sh <scenario>` needs a display.
- Commit with `git -c user.name="Benjamin Zigh" -c user.email="78459259+beben-games@users.noreply.github.com" commit` and end every message with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Commit generated `.uid` and `.import` files. Run `tools/test.sh` (which runs `--import`) before `git add -A` so the `.uid` files exist.
- Headless generator scripts run as `"$GODOT_BIN" --headless --path . -s tools/<script>.gd -- <args> </dev/null`. A failed `assert` in such a script does NOT quit the process; it hangs. Generators therefore report errors with `push_error` and `quit(1)`, and you run them with a deadline: `perl -e 'alarm 120; exec @ARGV' "$GODOT_BIN" ...`. Get `GODOT_BIN` with `source tools/godot.sh`.
- GDScript in this project is fully typed. Two engine quirks that bit the probes: a loop variable over a literal array needs a type (`for d: Vector2i in [...]`), and an inferred `:=` from an integer division or a `Dictionary.get` fails to parse ("Cannot infer the type"); write `var half: int = r.size.x / 2`.
- Physics callbacks: `room_cleared` and `enemy_died` arrive from inside a shot's `body_entered`. Anything that adds or frees physics nodes, or pauses the tree, from those handlers must `call_deferred`.
- Pause facts, verified by probe: with `get_tree().paused = true`, a `CanvasLayer` whose `process_mode` is `PROCESS_MODE_ALWAYS` keeps running `_process`, `_physics_process`, and input; ordinary nodes stop; `get_tree().physics_frame` still fires (so `await ticks(n)` works under a pause); `create_timer(t, true, false, true)` still fires. `Input.is_action_just_pressed` polls fine from an always-processing node.
- Raycast facts, verified by probe: `PhysicsRayQueryParameters2D.create(from, to, 16)` with `get_world_2d().direct_space_state.intersect_ray()` works inside an `Area2D._physics_process` and returns `position`, `normal`, `collider`. The reflection off a wall is `direction.bounce(normal)`, not `reflect`.
- Assets that arrive from the user's Downloads are copied into `assets/` in Task 5; the paths are listed there. Do not download anything.
- The plan deviates from the design's build order in one place: assets (icons, frames, font) land before the menu (Task 5 before Task 6) so the menu is built once with its final look. Record any further deviation in the "Deviations" section at the end of this file as you go.

- (Planning) The 0x72 UI sheet does carry its font (white glyphs, invisible on a white background). The design's "font fallback" is not needed: `tools/gen_ui_font.gd` builds a BMFont from it, with `+ - . , : / % '` drawn by hand because the sheet has no punctuation.
- (Planning) Assets land in Task 5, before the menu, rather than at step 8 of the design's build order, so the menu is built once with its final look.
- (Planning) The pool can never be empty while two weapons exist (a switch card is always offered), so the "empty pool skips the picker" path has no test; it stays in `Main._offer_upgrade` as a guard.
- Task 1 review: `Modifier.is_known_stat` replaces the second `validate()` call in `UpgradeDef._check_stats`, so a modifier on the wrong stat list is reported next to its other errors instead of being hidden by them (a PLAYER card naming `damage` with `mul 0` used to report only the mul). HEAL now rejects a set `weapon_id` like PLAYER does. `tests/test_weapon_def.gd` pins every name in `Modifier.WEAPON_STATS` to a real `WeaponDef` property and every `INT_STATS` name to a known stat, and checks each of the ten `must be >= 0` messages by name, because `Object.set` on a misspelled property is a silent no-op that would make a dead card. Coverage added for `Modifier.apply`, an unknown stat, a null modifier, and PLAYER/HEAL cards with a `weapon_id`.
- Task 2 review: `Build` rounded int stats per rank in `resolve` but only once at the end of `_fold_player`, so a `mul` on `max_hp` or `dash_charges` would have folded differently from a `mul` on `projectile_count`.
